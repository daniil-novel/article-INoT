\title[Hybrid-INoT: a hybrid agent architecture with internal role segregation]{Hybrid-INoT: a hybrid agent architecture with internal role segregation for engineering tasks under long shared context}

\author*[1]{\fnm{Daniil} \sur{Privezentsev}}\email{daprivezentsev@edu.hse.ru}

\affil*[1]{\orgname{National Research University Higher School of Economics}, \orgaddress{\city{Moscow}, \country{Russia}}}

\abstract{External multi-agent orchestration repeatedly transmits shared context to separate large-language-model roles, increasing token usage. We propose \textbf{Hybrid-INoT}, a hybrid system in which planner, worker, and critic roles share one model call, whereas verification and tool execution remain external. An artifact-backed evaluation compares the complete B3 package---combined call plus deterministic context compression above 4,096 tokens---with an uncompressed three-call B2 baseline. In a real Gemini~3.1~Pro Preview API pilot ($n=5$ unique tasks) B3 reduced mean token consumption by 55.6--88.9\% over target contexts of 256--16,384 tokens; an independent Gemini~3.1~Flash-Lite replication ($n=20$, seed 42) yielded 49.6--90.3\% savings. For Flash-Lite, mean within-task $U_{\mathrm{tok}}$ gains were 106.5, 144.8, 183.3, and 934.6\%, and every observed pair exceeded 15\%; a conditional signed-rank sensitivity analysis survived Holm correction ($p=9.54\cdot10^{-7}$ each). Four-cell, per-task OLS summaries were 3.425 for B2 and 0.219 for B3 tokens per context token (conditional paired $p=1.91\cdot10^{-6}$); they are not marginal derivatives across the compression boundary. These are system-package effects, not an isolated orchestration effect. Both architectures attained pass@1${}=1.0$; with zero harmful outcomes among only 20 unique pairs, an iid-binomial planning reference gives a 13.91-point one-sided upper bound, so 2-point quality non-inferiority is not established. An exploratory small-model screen agrees perfectly with retained HumanEval outcomes but poorly with an approximate SWE-bench Lite protocol; the policy effect was not evaluated. The Pro pilot yields \$429.96 API-inference savings per 10,000 tasks; task-cluster resampling gives a \$417.33--\$442.90 stability range, not a population interval or full-TCO estimate. The evidence supports a long-context resource-efficiency mechanism in the fixed task sets while leaving quality preservation, router effectiveness, component attribution, and real-repository transfer open.}

\keywords{Large language models, agent systems, Introspection of Thought, token efficiency, inference economics, HumanEval, reproducible experiment}

\section{Introduction}\label{sec:intro}

A modern software-engineering agent must successively understand the task specification, retrieve the relevant context from a repository, and construct a change that can then be checked by tests or static analysis. In practice, these functions are often distributed across several roles: one role builds a plan, another proposes a solution, a third critiques the intermediate result, and a fourth runs external verification. This decomposition is conceptually convenient, but it becomes expensive when all roles are forced to reread the same long context.

This paper focuses precisely on that setting: tasks in which the code, documentation, compiler messages, and execution logs are shared across all roles. We are interested not only in the final solution quality but also in the cost of the chosen orchestration scheme in tokens, response time, and monetary spending. The article therefore compares classical external multi-agent organization with a hybrid scheme in which part of the role discussion is moved inside a single model call.

\subsection{The problem of repeated context transmission and its practical significance}

In agent systems built on large language models, a typical configuration is external multi-agent orchestration (\textrm{Classical-MAS}): separate processes or calls implement the planner, worker, critic, and tester roles \cite{hong2023metagpt,qian2023chatdev,guo2024survey}. In software-engineering tasks, where several roles read the same long fragments of code, logs, and documentation, this scheme has a structural defect: \emph{each role receives the shared context $\mathcal{C}_0$ anew}, and additional coordination messages circulate between roles. In token-budget terms, this yields the term
\[
D_{\text{ctx}}=\Theta(|\mathcal{A}|\cdot|\mathcal{C}_0|),\qquad
H_{\text{coord}}=O(|\mathcal{A}|^2\cdot\bar{h}),
\]
where $|\mathcal{A}|$ is the number of roles and $\bar{h}$ is the average coordination-message length. The coordination term is a topology-dependent all-pairs upper order, not a universal quadratic lower bound. In our API pilot, repeated input transmission was observed directly. At a target context of 16,384 tokens, \textrm{Classical-MAS} used 59,631 tokens per task on average, of which 57,485 (96.4\%) were input tokens; \textrm{Hybrid-INoT} used 6,608 tokens. Per-case cost was \$0.14072 and \$0.02949, respectively, at the recorded Gemini~3.1~Pro Preview prices~\cite{openrouterpro2026}. These values concern the first five HumanEval tasks and must not be generalized to a different task distribution without measurement.

The problem is therefore quantitatively observable: in the studied long-context regime, repeated input transmission produced an approximately ninefold difference in total tokens between B2 and B3. The remainder of the paper separates the analytical model from empirical evidence and restricts claims to completed pilots.

\subsection{Existing approaches and their limitations}

The closest design space is broader than a self-reflection-versus-MAS dichotomy. It includes single-model refinement~\cite{madaan2023selfrefine,shinn2023reflexion}, reasoning--action agents~\cite{yao2022react,yang2024sweagent}, multi-persona prompting within one LLM~\cite{wang2024spp}, role collaboration through a shared blackboard~\cite{dong2024selfcollaboration}, sparse external debate~\cite{zeng2025s2mad}, and deliberately simple repository-repair pipelines such as Agentless~\cite{xia2024agentless}. Hybrid-INoT builds directly on INoT~\cite{sun2025inot}. Its claimed novelty is therefore deliberately narrow: an operational integration of an internal planner--worker--critic call, deterministic context selection, external verification, an explicit deployment router, and auditable resource accounting. We do not claim invention of role prompting, self-critique, compression, or tool verification in isolation.

The paper delivers the following results:

\section{Related work and distinction of the proposed approach}\label{sec:related}

\subsection{From chain-of-thought to internal role debate}

Wei et al.~\cite{wei2022cot} show that explicit verbalization of intermediate reasoning steps can improve solution quality on tasks that require several connected logical transitions. In this context, intermediate steps are textual fragments by which the model decomposes a complex inference into a sequence of local subproblems, while quality refers to the final success of solving the target task. The \textrm{Self-Refine} approach \cite{madaan2023selfrefine} formalizes a ``generator--feedback--revision'' cycle inside a single model; \textrm{Reflexion} \cite{shinn2023reflexion} supplements such a scheme with reflective memory, whereas \textrm{ReAct} \cite{yao2022react} couples internal reasoning with external actions and tools. Sun and Zeng \cite{sun2025inot} describe \textit{Introspection of Thought} (INoT) as a structured internal debate among several roles. At the same time, Turpin et al.~\cite{turpin2023unfaithful} show that intermediate chain-of-thought text should not be interpreted as a faithful description of the hidden computational process. Accordingly, in the present paper introspection is treated primarily as a computational mechanism for candidate selection, critique, and selective rerun rather than as a literal window into the latent state of the model.

\subsection{Multi-agent systems for software engineering}

Weiss \cite{weiss1999} and Wooldridge \cite{wooldridge2009} provide the theoretical framework for MAS. MetaGPT \cite{hong2023metagpt} and ChatDev \cite{qian2023chatdev} transfer this framework into the context of large language models: roles are implemented as separate calls, each receiving its own copy of the context. Survey work identifies two key limitations of Classical-MAS: error propagation along the chain and the growth of coordination cost \cite{guo2024survey,qian2024scaling}. SWE-bench and SWE-agent \cite{jimenez2023swebench,yang2024sweagent} further show that practical software-engineering automation requires long context and iterative editing, which makes the retransmission problem $D_{\text{ctx}}$ even more acute.

Single-Persona Prompting (SPP) simulates several personas through multi-turn prompting of one LLM~\cite{wang2024spp}; Self-Collaboration Code Generation coordinates specialized roles through a shared blackboard and a linguistic tester~\cite{dong2024selfcollaboration}; S2-MAD reduces the communication graph of external debate~\cite{zeng2025s2mad}. Agentless, in contrast, demonstrates that a compact localization--repair--validation pipeline can be a strong software-engineering baseline without a complex agent society~\cite{xia2024agentless}. These works make component-level baselines and call topology essential to any novelty claim.

\subsection{Context compression and external verification}

LongLLMLingua and LLMLingua-2 \cite{jiang2023longllmlingua,pan2024llmlingua2} demonstrate that prompt compression can preserve or even improve quality under long context while lowering cost. Jia et al.~\cite{jia2026compression} apply this logic directly to code. For code self-check, linguistic reflection alone is insufficient: external observable signals are required, namely tests, static analysis, and compiler feedback~\cite{bi2024cocogen,su2025static,sepidband2025complexity}.

\section{Formal problem statement}\label{sec:problem}

\subsection{Task}

Let $\mathcal{X}$ denote the set of textual task specifications, $\mathcal{C}$ the set of finite sequences of contextual artifacts (code files, documentation fragments, and execution logs), and $\mathcal{Y}$ the set of candidate solutions representable as textual artifacts and amenable to external verification. Let $(\Omega,\mathcal{F},\mathbb{P})$ be the probability space induced by stochastic model generation, seed choice, and nondeterminism in external tool calls.

\begin{definition}[Agentic engineering task]\label{def:task}
An agentic engineering task is the tuple $(x,\mathcal{C}_0,\mathcal{Z},\mathcal{V})$, where $x\in\mathcal{X}$ is a textual task description; $\mathcal{C}_0\in\mathcal{C}$ is the initial task context, including code, documentation, and execution logs; $\mathcal{Z}$ is a finite set of permitted external tools; and $\mathcal{V}:\mathcal{Y}\to\{0,1\}$ is an externally verifiable success function, for example, the execution of a test suite.
\end{definition}

The agent strategy induces a random output $Y:\Omega\to\mathcal{Y}$. At the same time, random variables $T:\Omega\to\mathbb{R}_{\ge 0}$, $C_{\text{inf}}:\Omega\to\mathbb{R}_{\ge 0}$, and $\ell:\Omega\to\mathbb{R}_{\ge 0}$ are defined, representing, respectively, the total token consumption, the monetary inference cost, and the latency of solving one task. The goal of the agent is to maximize $\E[\mathcal{V}(Y)]$ under the budget constraints $\E[T]\le B$, $\E[C_{\text{inf}}]\le B_\$$, and $\E[\ell]\le B_\ell$.

\subsubsection*{Main notation}
\begin{description}
\item[$\mathcal{C}_0$] --- the initial shared task context; $|\mathcal{C}_0|$ is its token length.
\item[$\hat{\mathcal{C}}$] --- the compressed version of the initial context used in the internal cycle.
\item[$\mathcal{A}$] --- the set of external roles in the \textrm{Classical-MAS} scheme; $|\mathcal{A}|$ is the number of such roles.
\item[$Y$] --- the random output of the agent with values in $\mathcal{Y}$; $y\in\mathcal{Y}$ is an individual candidate solution.
\item[$K$] --- the number of candidates generated by the role $r_{\text{work}}$ in one iteration of the internal cycle.
\item[$T$] --- the random variable of total token consumption for one task; $\E[T]$ is taken with respect to the distribution defined on $(\Omega,\mathcal{F},\mathbb{P})$.
\item[$U_{\text{tok}}$] --- the token-efficiency measure defined as the ratio of final solution quality to total token consumption.
\item[$\tau^\star$] --- a theoretical crossover implied only when the sufficient accounting assumptions hold; it is not identified by E3.
\item[$\delta_{H1}$] --- the minimal practically relevant gain in $U_{\text{tok}}$ used in Hypothesis~H1.
\item[$C_{\text{check}}^S$] --- the cost of the preliminary check performed by the small model.
\item[$C_{\text{rerun}}^L$] --- the cost of rerunning the large model.
\item[$\rho_0,\rho_1$] --- the probabilities of an expensive rerun without and with the preliminary check, respectively.
\end{description}

\subsection{Research hypotheses}

\begin{description}
\item[\textbf{H1} (advantage under long context).] There exists a threshold initial-context length $\tau^\star$ such that for $|\mathcal{C}_0|>\tau^\star$, \textrm{Hybrid-INoT} yields at least a $\delta_{H1}=15\%$ increase in $U_{\text{tok}}$ relative to \textrm{Classical-MAS}, while pass@1 degrades by no more than 2 percentage points.\par\emph{Verification:} E3 (§\ref{subsec:e3}) reports the finite-set mean and pairwise threshold counts; Wilcoxon tests, task-resampling ranges, and Holm correction are conditional sensitivity analyses rather than design-based population inference.
\item[\textbf{H2} (economic justification of the small self-check model).] There exists a regime in which a small-model preliminary check reduces expensive reruns enough for $C_{\text{check}}^S<(\rho_0-\rho_1)C_{\text{rerun}}^L$.\par\emph{Intended verification:} an integrated policy experiment recording per-case rerun decisions and costs. The retained E4 (§\ref{subsec:e4}) does not satisfy this design and is reported only as an exploratory screening diagnostic.
\item[\textbf{H3} (boundary of applicability).] On tasks with genuinely independent subtasks and parallel tools, the response-time advantage of Hybrid-INoT vanishes or becomes negative.\par\emph{Verification:} an architectural comparison on five tasks and a separate controlled serial/parallel tool microbenchmark in E2c (§\ref{subsec:e2}).
\end{description}

When testing H1, model, tools, verification, task, seed, temperature, and task prompt are matched within each pair. The treatment is nevertheless a \emph{system bundle}: B2 uses three calls over uncompressed context, while B3 combines the role prefixes in one call and applies deterministic selection above 4,096 tokens. Thus E3 identifies the package effect, not the isolated causal contribution of orchestration or compression. The threshold $\delta_{H1}=15\%$ is treated as the minimum practically meaningful effect; observed resource savings do not replace evaluation of the full conjunctive H1 criterion.

\section{Method: Hybrid-INoT}\label{sec:method}

\subsection{States and role signatures}

Define the system state as $\sigma=(x,\hat{\mathcal{C}},\mathcal{H},i)$, where $\hat{\mathcal{C}}$ is the compressed context, $\mathcal{H}$ is the history of iterations, and $i\in\{0,\dots,I\}$ is the iteration counter. The evaluated client maintains a separate experiment-level monetary counter and rejects a request whose estimated charge would cross the configured hard cap.

Let $\Pi$ be the space of plans, and let $K\in\mathbb{N}$ denote the number of candidates generated by the role $r_{\text{work}}$ in one iteration. Then each role is defined by a signature $r:\mathcal{S}_r^{\text{in}}\to\mathcal{S}_r^{\text{out}}$:
\begin{align*}
r_{\text{plan}} &:(x,\hat{\mathcal{C}})\mapsto \pi\in\Pi, \\
r_{\text{work}} &:(\pi,\hat{\mathcal{C}},K)\mapsto \mathbf{y}=(y_1,\dots,y_K)\in\mathcal{Y}^K, \\
r_{\text{crit}} &:(\mathbf{y},\hat{\mathcal{C}})\mapsto (s_1,\dots,s_K)\in[0,1]^K, \\
r_{\text{self}} &:(y\in\mathcal{Y})\mapsto (v,M,e)\in\{0,1\}\times[0,1]\times\mathcal{E}.
\end{align*}
The roles $r_{\text{plan}},r_{\text{work}},r_{\text{crit}}$ are implemented as role prefixes inside \emph{one} large-model call over the shared $\hat{\mathcal{C}}$; the role $r_{\text{self}}$ is an external process running tests and static analysis.

\subsection{Routing function}

\begin{definition}[RouteMode]\label{def:routemode}
Let $\varphi_{\mathrm{tool}}(x)\in\{0,1\}$ read the Boolean \texttt{requires\_tool} task-metadata field and let $\varphi_{\mathrm{par}}(x)\in\{0,1\}$ indicate whether the metadata field \texttt{parallelism} is at least two. The implemented rule at the pinned research commit is
\[
\texttt{RouteMode}(x)=\begin{cases}\texttt{external}, & \varphi_{\mathrm{tool}}(x)=1 \;\lor\; \varphi_{\mathrm{par}}(x)=1,\\ \texttt{internal}, & \text{otherwise}.\end{cases}
\]
The pinned code does not infer these flags from arbitrary task instructions: the benchmark loader supplies them for the synthetic tool tasks. A learned or instruction-based metadata classifier and a context-length gate are possible deployment extensions, but neither is present in the evaluated commit. E3 forces the internal B3 treatment at every context cell and therefore evaluates neither the router nor any routing threshold.
\end{definition}

\subsection{Internal cycle and termination condition}

\begin{algorithm}[htbp]
\caption{Hybrid-INoT: internal introspective cycle}\label{alg:main}
\begin{algorithmic}[1]
\Require task $x$, context $\mathcal{C}_0$, maximum iterations $I$, candidates $K$, rerun limit $R$
\Ensure solution $y^\star$, flag $v^\star$, score $M^\star$
\State $\mathcal{C}\gets\texttt{PolicySanitize}(x,\mathcal{C}_0)$
\State $\hat{\mathcal{C}}\gets\texttt{CompressIfNeeded}(\mathcal{C})$ \Comment{Alg.~\ref{alg:compression}}
\State $m\gets\texttt{RouteMode}(x)$ \Comment{Def.~\ref{def:routemode}}
\If{$m=\texttt{external}$} \Return \texttt{ExternalAgentWorkflow}$(x,\hat{\mathcal{C}})$ \EndIf
\State $s^{\text{best}}\gets-\infty;\; s^{\text{prev}}\gets-\infty;\; y^{\text{best}}\gets\bot;\; r\gets0;\; e\gets\varnothing$
\For{$i=1$ to $I$}
 \State $(\pi_i,\{y_{i,k}\},\{s_{i,k}\})\gets\texttt{CombinedLargeModelCall}(x,\hat{\mathcal{C}},K,e)$
 \Comment{one API call with planner/worker/critic prefixes}
 \State $k^\star\gets\arg\max_k s_{i,k};\; y_i\gets y_{i,k^\star}$
 \If{$s_{i,k^\star}>s^{\text{best}}$} $s^{\text{best}}\gets s_{i,k^\star};\; y^{\text{best}}\gets y_i$ \EndIf
 \State $(v_i,M_i,e_i)\gets r_{\text{self}}(y_i)$ \Comment{$e_i$: verified tool output}
 \If{$v_i=1$} \Return $(y_i,1,M_i)$ \EndIf
 \State $e\gets\texttt{Truncate}(e_i,600)$
 \If{$r<R$}
   \State $(y'_i,v'_i,M'_i,e'_i)\gets\texttt{SelectiveRerun}(x,\{y_{i,k}\},\{s_{i,k}\})$; $r\gets r+1$
   \If{$v'_i=1$} \Return $(y'_i,1,M'_i)$ \EndIf
 \EndIf
 \If{$i>1\land s_{i,k^\star}-s^{\text{prev}}<\varepsilon$} \textbf{break} \Comment{see Prop.~\ref{prop:convergence}}\EndIf
 \State $s^{\text{prev}}\gets s_{i,k^\star}$
\EndFor
\State \Return $(y^{\text{best}},0,M(y^{\text{best}}))$
\end{algorithmic}
\end{algorithm}

\begin{proposition}[Termination of the internal cycle]\label{prop:convergence}
Assume that each operation within one iteration of Algorithm~\ref{alg:main} terminates in finite time and that the number of iterations is bounded above by the parameter $I$. Then the algorithm terminates no later than after $I$ iterations: it either returns a solution after a successful external check, stops after iteration $i>1$ when $s_{i,k^\star}-s^{\text{prev}}<\varepsilon$, or, after exhausting the iteration limit, returns the best candidate found.
\end{proposition}

\begin{proof}
The outer loop over the index $i$ contains at most $I$ passes. Each iteration consists of a finite sequence of steps: plan construction, generation of $K$ candidates, critical scoring, external verification, and context update. By assumption, all of these operations terminate in finite time; therefore, each iteration also terminates. Consequently, the algorithm either stops early by the instructions \textbf{return} or \textbf{break}, or reaches the final \textbf{return} after the $I$-th iteration. Hence the running time of the internal cycle is bounded above by a finite number of iterations, which proves the statement.
\end{proof}

\subsubsection*{Note}
Proposition~\ref{prop:convergence} guarantees only algorithm termination; it does not imply monotonic growth of the scores $s_i$, nor does it guarantee the correctness of the critic itself. The scenario in which the critic systematically endorses incorrect solutions is examined separately in E2b (§\ref{subsec:e2}) as one of the threats to validity.

\subsection{Context compression}

\begin{algorithm}[htbp]
\caption{Compression of long context}\label{alg:compression}
\begin{algorithmic}[1]
\Require $\mathcal{C}_0$, length threshold $\tau_{\text{len}}$
\Ensure $\hat{\mathcal{C}}$
\If{$|\mathcal{C}_0|\le\tau_{\text{len}}$} \Return $\mathcal{C}_0$ \EndIf
\State split $\mathcal{C}_0$ into text blocks $\{b_j\}$ and extract task identifiers
\State $\text{rel}(b_j)\gets 5\,r_{\mathrm{id}}(b_j)+2\,\mathbb{I}_{\mathrm{sig}}(b_j)+4\,\mathbb{I}_{\mathrm{err}}(b_j)-0.001\,|b_j|$
\State retain signature/error blocks; then add remaining blocks by descending $\text{rel}(b_j)$
\State \Return blocks whose summed proxy counts fit $\tau_{\text{len}}=4096$
\end{algorithmic}
\end{algorithm}

Here $r_{\mathrm{id}}$ is the fraction of task identifiers present in a block, while $\mathbb{I}_{\mathrm{sig}}$ and $\mathbb{I}_{\mathrm{err}}$ mark signatures and error/log text. The implementation budgets the sum of block proxy counts but joins retained blocks with separators afterward; consequently, the serialized context can slightly exceed 4,096 proxy tokens (the observed E3 maximum is 4,170). This deterministic lexical proxy is inspired by learned prompt compression~\cite{jiang2023longllmlingua,pan2024llmlingua2}, but it is not an LLMLingua-2 classifier. Stating the deployed score and this boundary behavior makes the treatment reproducible and prevents attributing its effect to a model that was not run.

\subsection{Selective rerun}

\begin{algorithm}[htbp]
\caption{Selective rerun based on verified signals}\label{alg:rerun}
\begin{algorithmic}[1]
\Require task $x$, candidates $\{y_1,\dots,y_K\}$, scores $\{s_k\}$
\Ensure $(y^\star,v^\star,M^\star,e^\star)$
\State sort $\{y_k\}$ in descending order of $s_k$; keep the top $M\le K$
\For{each $y_m$}
  \State $(v_m,M_m,e_m)\gets r_{\text{self}}(y_m)$
  \If{$v_m=1$} \Return $(y_m,1,M_m,e_m)$ \EndIf
\EndFor
\State construct one correction prompt from $x$, the top candidate, and $\texttt{Truncate}(e_m,600)$
\State $y'\gets\texttt{LargeModelRerun}(\text{prompt})$
\State $(v',M',e')\gets r_{\text{self}}(y')$
\State \Return $(y',v',M',e')$
\end{algorithmic}
\end{algorithm}

\section{Analytical model of token and monetary costs}\label{sec:analysis}

\subsection{Structure of the analytical relations}

The analysis in this section includes two types of relations. The first comprises direct balance equalities and inequalities that define the structure of token and monetary costs. The second comprises statements comparing architectures under fixed assumptions about context length, coordination cost, and internal critique. This separation makes it possible to distinguish general accounting relations from results that require additional assumptions.

\subsection{Token budgets of \textrm{Classical-MAS} and \textrm{Hybrid-INoT}}

\begin{assumption}\label{as:ctx}
In each of $I$ iterations of \textrm{Classical-MAS}, at least $\alpha|\mathcal{A}|$ roles, with $\alpha\in(0,1]$, read the shared context $\mathcal{C}_0$ in full. Hybrid-INoT uses context $\hat{\mathcal{C}}$ satisfying $|\hat{\mathcal{C}}|\le q_{\max}|\mathcal{C}_0|$ for a fixed $q_{\max}\le1$.
\end{assumption}

\begin{assumption}\label{as:bounded}
For coefficients $\gamma,\beta\ge0$, the one-off compression cost satisfies $T_{\text{cmp}}\le\gamma|\mathcal{C}_0|$, the additional internal-role cost satisfies $T_{\text{core}}^{\text{add}}\le\beta|\hat{\mathcal{C}}|$, and the absolute difference between all remaining generation, verification, and rerun terms of the two systems is bounded by a constant $K_0$ independent of $|\mathcal{C}_0|$.
\end{assumption}

\begin{proposition}[Sufficient accounting condition]\label{prop:inot-vs-mas}
Let
\[
A_0=I\alpha|\mathcal{A}|-(I+\beta)q_{\max}-\gamma.
\]
Under Assumptions~\ref{as:ctx}--\ref{as:bounded}, if $A_0>0$, then
\[
\E[T_{\text{MAS}}-T_{\text{INoT}}]\ge A_0|\mathcal{C}_0|-K_0,
\]
and the expected token difference is positive for $|\mathcal{C}_0|>K_0/A_0$.
\end{proposition}

\begin{proof}[Accounting derivation]
Assumption~\ref{as:ctx} gives the context-transmission lower bound
\[
T_{\text{ctx}}^{\text{MAS}}\ge I\cdot\alpha|\mathcal{A}|\cdot|\mathcal{C}_0|.
\]
For Hybrid-INoT, the repeated selected-context term, internal-role overhead, and compression together are bounded by
\[
(I+\beta)|\hat{\mathcal{C}}|+\gamma|\mathcal{C}_0|
\le\bigl((I+\beta)q_{\max}+\gamma\bigr)|\mathcal{C}_0|.
\]
Subtracting these terms and applying the $K_0$ bound to all residual differences yields $A_0|\mathcal{C}_0|-K_0$. If $A_0>0$, this lower bound is positive exactly when $|\mathcal{C}_0|>K_0/A_0$.
\end{proof}

\subsubsection*{Scope of applicability}
Proposition~\ref{prop:inot-vs-mas} is a sufficient accounting result, not a causal theorem about orchestration and not an empirical validation of a router. Coordination traffic, if nonnegative, can only strengthen the bound but is not used as an unsupported asymptotic lower bound. E3 estimates slopes of the evaluated B2/B3 packages; because no crossover is bracketed, it cannot identify $K_0/A_0$ or a deployment threshold.

\subsection{Request-count identity and output cap}

The implementation produces all $K$ candidates, the plan, and the critique in one core call per iteration; multiplying a per-candidate prompt by $K$ would therefore double-count the shared prompt. Let $N_{\mathrm{core}}\le I$ and $N_{\mathrm{rerun}}\le\min(I,R)$ be the realized numbers of core and rerun calls, and let $P$ and $O$ denote the provider-recorded input and output tokens of an individual call. For the internal route, model-token accounting is the identity
\begin{equation}
T_{\mathrm{INoT}}^{\mathrm{internal}}
=\sum_{i=1}^{N_{\mathrm{core}}}\bigl(P_{\mathrm{core},i}+O_{\mathrm{core},i}\bigr)
+\sum_{j=1}^{N_{\mathrm{rerun}}}\bigl(P_{\mathrm{rerun},j}+O_{\mathrm{rerun},j}\bigr).
\label{eq:request-accounting}
\end{equation}
The pinned implementation sets provider output caps $O_{\mathrm{core},i}\le2048+700K$ and $O_{\mathrm{rerun},j}\le1024$, hence
\[
T_{\mathrm{out}}\le N_{\mathrm{core}}(2048+700K)+1024N_{\mathrm{rerun}}.
\]
Compression is deterministic and incurs no model call. Its block-sum budget is 4,096 proxy tokens, but join separators are excluded from that counter, so the serialized E3 context reaches at most 4,170 proxy tokens. No corresponding hard bound exists for total input tokens because the task prompt is not capped and proxy counts need not equal provider tokenization. The evaluated code enforces a pre-request monetary cap at the shared API client, but not a per-task token counter. We therefore report the exact recorded identity and output-only cap, not a hard total-token guarantee.

\subsection{Profitability condition for the small self-check model}

Inference cost:
\begin{equation}
C_{\text{inf}}=c_L^{\mathrm{in}}\textstyle\sum_i p_i^L+c_L^{\mathrm{out}}\sum_i r_i^L+c_S^{\mathrm{in}}\sum_i p_i^S+c_S^{\mathrm{out}}\sum_i r_i^S.
\label{eq:cost-inference}
\end{equation}

\noindent Under a two-scenario accounting model with exactly one preliminary check, at most one avoided rerun, and a constant rerun cost, a small self-check model is economically beneficial if and only if
\begin{equation}
C_{\text{check}}^S<(\rho_0-\rho_1)\cdot C_{\text{rerun}}^L.
\label{eq:small-model-condition}
\end{equation}
The left-hand side is the cost of the preliminary check, whereas the right-hand side is the expected savings \emph{if an integrated policy actually prevents some large-model reruns}. Inequality~\eqref{eq:small-model-condition} is therefore a prospective design condition. The retained E4 harness records only aggregate screening agreement and does not implement or identify the policy effect $\rho_0-\rho_1$.

\section{Metric system}\label{sec:metrics}

\subsection{Main metrics and the rationale for the aggregation form}

\begin{align}
U_{\text{tok}}=\frac{Q}{T},\qquad Q_{\$}=\frac{Q}{C_{\text{inf}}},\qquad \mathrm{VCR}=\frac{1}{N}\sum_i\I[\text{tests}_i=1\land\text{static}_i=1\land\text{sec}_i=1].\label{eq:metrics-main}
\end{align}

For heterogeneous quality, the paper uses a weighted sum over task classes, $Q=\sum_b w_b Q_b$, with weights specified in Table~\ref{tab:weights}.

\subsection{Aggregated success metric and its form}

The aggregated success metric is defined as
\begin{equation}
\mathrm{MAS}_i=\min(\mathrm{Success}_i,\mathrm{Verified}_i)\cdot M_i^{\lambda},\qquad \lambda\in[0,1],\quad\lambda=0.5.
\label{eq:mas}
\end{equation}
The rationale for this construction is as follows. First, $\mathrm{Success}$ and $\mathrm{Verified}$ are necessary conditions for counting a solution as successful: a patch that fails external verification should not receive a high final score. Second, the multiplier $M_i^\lambda$ models the effect of maintainability on the final assessment; the parameter $\lambda$ controls the strength of this effect. The baseline uses $\lambda=0.5$; E2d produced seven ranking inversions under weight and $\lambda$ changes, so the composite metric is treated as secondary.

\subsection{Maintainability weights and their rationale}

\begin{equation}
M_i=w_{\mathrm{cc}}(1-\widehat{\mathrm{CC}}_i)+w_{\mathrm{dup}}(1-\widehat{\mathrm{Dup}}_i)+w_{\mathrm{warn}}(1-\widehat{\mathrm{Warn}}_i)+w_{\mathrm{doc}}\widehat{\mathrm{Doc}}_i.
\label{eq:maintainability}
\end{equation}

E2d tested the robustness of the configuration ranking under $(w_{\mathrm{cc}},w_{\mathrm{dup}},w_{\mathrm{warn}},w_{\mathrm{doc}})\pm 20\%$ and $\lambda\in\{0,0.25,0.5,0.75,1\}$ in~\eqref{eq:mas}; seven reversals were observed.

\begin{align}

\end{align}

\section{Empirical validation}\label{sec:eval}

\subsection{Reproducibility, source data, and statistical protocol}\label{subsec:e1}

The research harness is published in the INoT\_Research repository~\cite{inotresearch2026}; every result below is tied to commit \texttt{010211ee5775185e8330ab6cde06e912c2adcb9e}. The built-in configuration check completed successfully, and the test suite reported 15 passing tests. Raw JSON inputs are stored under \texttt{results/slide\_e2e3\_real}, \texttt{results/e6}, and \texttt{reproducibility/results/20260726\_flash\_lite}. Their portable relative paths, SHA-256 hashes, aggregates, and figure-generation code are captured in \texttt{reproducibility/evidence\_snapshot.json}. Grid checks found 60/60 expected Pro rows and 240/240 Flash-Lite rows, with no duplicate keys, missing cells, token-accounting mismatches, or usage-trace mismatches. The unit of analysis is task $\times$ architecture $\times$ target context $\times$ seed.

The primary dataset is canonical HumanEval~\cite{chen2021humaneval}. The Pro pilot uses HumanEval/0--4, and the Flash-Lite replication uses HumanEval/0--19 in canonical order. Historical context is generated deterministically (seed 42) from prompts and canonical solutions of \emph{other} HumanEval tasks; the target task solution is excluded. Whole blocks are appended, so actual lengths exceed targets. For $n=20$ and targets $\{256,1024,4096,16384\}$, mean actual lengths are $\{371.2,1154.8,4210.6,16524.3\}$ tokens, with ranges $\{259$--$545,\ 1024$--$1411,\ 4100$--$4415,\ 16389$--$16946\}$. This context is reproducible but synthetic.

B2 Classical-MAS invokes planner, worker, and critic separately over the uncompressed shared context. B3 combines those role instructions in one call and applies Algorithm~\ref{alg:compression} only above 4,096 tokens; external verification follows generation. Thus the primary estimand is an end-to-end package contrast, not an isolated orchestration effect. E3 runs B3 in internal mode throughout, so it does not evaluate \texttt{RouteMode}. Models are \texttt{google/gemini-3.1-pro-preview} and \texttt{google/gemini-3.1-flash-lite}. Recorded prices are \$2/\$12 and \$0.25/\$1.50 per million input/output tokens, respectively~\cite{openrouterpro2026,openrouterflash2026}, fixed on 26 July 2026. These API aliases are not immutable weight snapshots, so provider drift remains possible.

For each context length, B2 and B3 are paired on task and seed. We report
\begin{align}
S_T &= 100\left(1-\frac{\overline{T}_{B3}}{\overline{T}_{B2}}\right), &
S_C &= 100\left(1-\frac{\overline{C}_{B3}}{\overline{C}_{B2}}\right), \label{eq:empirical-savings}\\
\Delta U_{\mathrm{tok}} &= 100\left(\frac{U_{\mathrm{tok}}^{B3}}{U_{\mathrm{tok}}^{B2}}-1\right). \label{eq:empirical-utok}
\end{align}
Means, minima, and pairwise threshold counts are descriptive finite-set estimands. Wilcoxon signed-rank tests~\cite{wilcoxon1945} are reported only as conditional sensitivity analyses of a symmetric location shift; they do not test the reported mean. The 15\% analysis applies the one-sided signed-rank test to $\Delta U_{\mathrm{tok}}-15\%$, and each four-context family is adjusted by Holm's sequential procedure~\cite{holm1979}. Percentile ranges from $10^4$ task-level resamples describe stability to reweighting the observed tasks, not population confidence coverage. Binary quality is summarized by harmful discordance (B2 pass/B3 fail); the zero-event Clopper--Pearson calculation is an iid-binomial planning reference, not design-valid inference for the first non-random HumanEval tasks. The four repeated context cells are not treated as independent quality observations, and the single retained API run does not measure seed or provider-run variance.

\subsection{E2~--- Ablations, critic behavior, and parallelism}\label{subsec:e2}

The Pro ablation pilot contains five tasks. pass@1 is 1.0 for full B3 and variants without compression, critic, or self-check. Paired aggregate-success differences for full B3 against the three variants are $-0.0037$, $-0.0262$, and $0.0000$, with $p=1.0$, $0.5$, and $1.0$; none survives Holm correction. Component token-overhead shares are 36.6\% for compression, 29.7\% for the critic, and 33.8\% for self-check, but these are overhead allocations, not demonstrated independent quality contributions. Only two B0 failures were available for E2b; zero erroneous critic approvals in two cases do not establish critic reliability.

In E2c, mean B2 latency is 19.28~s and B3 latency 9.76~s, a $-49.4\%$ change; the task-resampling range for B3$-$B2 is $[-13.05,-6.83]$~s, while the conditional Wilcoxon test gives $p=0.0625$ at $n=5$. A separate deterministic tool microbenchmark shows serial execution to be 148.8\% slower than parallel execution, yet the direct architectural comparison does not show the predicted B3 penalty. H3 is therefore \emph{not supported}; the microbenchmark only confirms a mechanism requiring isolation on real independent-tool tasks. E2d produces seven ranking inversions under weight and $\lambda$ changes, with the no-critic variant ranked first canonically. The composite metric is therefore unstable and retained only as a secondary measure.

\section{Limitations and threats to validity}\label{sec:limits}

\begin{enumerate}
\item \textbf{Small, non-random samples.} The first 5 or 20 HumanEval tasks are used rather than a random stratified sample of 164; the new run has one seed.
\item \textbf{Synthetic context.} Long inputs are assembled from other HumanEval tasks rather than repository history. They isolate retransmission cost but not real codebase dependencies.
\item \textbf{Quality ceiling.} B2/B3 and controlled E6 have pass@1${}=1.0$, supporting a resource comparison but not a strong quality test.
\item \textbf{Bundled treatment.} B3 changes call topology and, above 4,096 tokens, context selection. Component attribution requires a factorial design; the present estimand is the end-to-end package.
\item \textbf{Approximate SWE-bench.} The official container harness is not used, so no claim about real issue resolution is made.
\item \textbf{Router not evaluated.} E3 always invokes internal B3; neither flag accuracy nor a context gate is tested.
\item \textbf{Post-hoc robustness analyses.} Four-cell OLS summaries, iid-reference harm bounds, and the corrected task-cluster resampling range were added after auditing the pilot. They are transparent diagnostics, not preregistered confirmatory endpoints.
\item \textbf{E4 auditability.} Per-case screen decisions and counterfactual rerun outcomes were not persisted, so H2 remains unevaluated.
\item \textbf{API drift.} Model names, parameters, usage, latency, and cost are recorded, but aliases do not guarantee immutable weights. Provider-limit failures are excluded.
\item \textbf{Limited answer auditability.} \texttt{runs.json} records metrics and usage but not complete final solution text.
\item \textbf{Cost is not TCO.} Figure~\ref{fig:e5-sensitivity} covers API inference only; the other terms in~\eqref{eq:tco} are unmeasured.
\item \textbf{Architectural boundaries.} Independent subtasks, process isolation, critic errors, and compression losses may eliminate the B3 advantage. Role text is a computational mechanism, not a faithful explanation of hidden reasoning~\cite{turpin2023unfaithful}.
\end{enumerate}

\section{Directions for further research}\label{sec:agenda}

The next study should remove the identified uncertainty rather than repeat the pilot:
\begin{enumerate}
\item preregister a full $2\times2$ factorial experiment crossing call topology (separate/combined) with context selection (off/on);
\item run at least 149 unique paired tasks with zero harmful outcomes---preferably all 164 HumanEval tasks and several seeds---for a 2-point exact non-inferiority target;
\item extend the context grid below 256 tokens and include both winning and losing regions before estimating any crossover or routing gate;
\item retain full input/output, prompt hashes, immutable model identifiers, and external-test results per run;
\item replace the approximate SWE-bench path with the official container harness on a random repository sample;
\item repeat E2c with real independent tools under matched models and serial/parallel execution;
\item compare B3 with Self-Refine, SPP, Self-Collaboration, S2-MAD, Agentless, ReAct, and SWE-agent under matched calls, context, and verification;
\item implement E4 as a randomized or paired policy experiment that persists every screen decision, rerun, final candidate, and cost;
\item measure full TCO, including operations, reruns, latency, infrastructure, and storage, under a production context-length distribution.
\end{enumerate}

\section{Conclusion}

Hybrid-INoT is evaluated as an integrated intermediate system between in-context role prompting and external multi-agent orchestration. Across two real-API pilots, the B3 package used 49.6--90.3\% fewer tokens than the matched B2 package; the Flash-Lite four-cell OLS summary is 3.425 for B2 and 0.219 for B3 tokens per context token. Every observed Flash-Lite pair exceeds the 15\% resource threshold, and the conditional rank-based sensitivity analysis survives multiplicity correction, but the full H1 is not established: 20 ceiling-quality, non-random pairs cannot establish a 2-point non-inferiority margin. H2 was not evaluated by the retained aggregate screening harness; H3 was not supported; routing and component attribution remain open. The \$429.96 estimate is fixed-mixture API-inference savings, not population-level TCO. The defensible conclusion is therefore strong but bounded: the complete B3 package reduces repeated long-context transmission in these controlled task sets, while quality, causal components, router utility, and real-repository impact require a powered preregistered study.
