## Proposed implementation approach
### 1. Use `json.dumps`
Serialize `my_obj` with `json.dumps`.

### 2. Provide a custom `default` handler
Create a function inside `task_func` or a helper that handles unsupported types:
- If the object is a `datetime`, convert it with `isoformat()`
- If the object is a `Decimal`, convert it to a JSON-compatible value

### 3. Decide how to encode `Decimal`
There are two common choices:
- **As a number** using `float(obj)`  
  - Pros: looks natural in JSON
  - Cons: may lose precision
- **As a string** using `str(obj)`  
  - Pros: preserves exact value
  - Cons: JSON consumer must parse it back

Given the requirement “properly serialized” and the presence of `Decimal`, the safer choice is often **string serialization** to avoid precision loss, unless the problem expects numeric JSON output.

### 4. Raise error for unsupported objects
If the object type is not supported by the custom handler, let `json.dumps` raise `TypeError` or explicitly re-raise a clear error. This keeps behavior predictable.

## Edge cases to consider
### 1. Nested structures
The object may contain `datetime` or `Decimal` inside:
- lists
- tuples
- nested dictionaries

The custom `default` handler should work recursively through `json.dumps`.

### 2. Timezone-aware datetimes
`datetime.isoformat()` preserves timezone information if present.

### 3. Naive datetimes
Naive datetimes should still serialize consistently using `isoformat()`.

### 4. Decimal precision
If `Decimal` is converted to `float`, precision may be lost:
- `Decimal('0.1')` is fine
- `Decimal('0.123456789123456789')` may lose exactness

If exact representation matters, serialize as string.

### 5. Unsupported custom objects
If an object is neither JSON-native nor one of the supported special types, the function should fail clearly rather than silently converting incorrectly.

### 6. Special floating values
If the input contains `float('nan')`, `inf`, or `-inf`, `json.dumps` has its own behavior unless configured otherwise. This task does not explicitly require special handling, but it’s worth noting.

### 7. None / booleans / integers / strings
These should serialize normally without any special handling.
