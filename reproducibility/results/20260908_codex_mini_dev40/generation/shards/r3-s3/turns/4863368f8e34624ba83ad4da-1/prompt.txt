## Goal
Process all `.json` files in a directory:
- read them **alphabetically by filename**
- convert each JSON file into a `pandas.DataFrame`
- add a `"Source"` column containing the filename
- combine all rows into one DataFrame
- move each successfully processed file into a `processed/` subdirectory
- create the input directory’s path components if needed, and ensure `processed/` exists

## Planned behavior

### 1) Validate / normalize the input path
- Treat `path` as the directory containing JSON files.
- Build `processed_dir = os.path.join(path, "processed")`.
- Ensure `processed_dir` exists before moving files.

### 2) Find JSON files
- List files in `path`.
- Select only regular files ending in `.json` (likely case-sensitive unless explicitly made case-insensitive).
- Sort filenames alphabetically.

### 3) Read and transform each file
For each JSON file in sorted order:
- open and load JSON using `json.load`
- convert loaded data into a DataFrame
- insert a `"Source"` column with the filename

### 4) Combine results
- Append each file’s DataFrame to a list.
- Concatenate all frames with `pd.concat(..., ignore_index=True)` if any exist.
- If no JSON files are found, return an empty DataFrame with at least the `"Source"` column or an empty DataFrame depending on expected convention.

### 5) Move processed files
- After successfully reading a file, move it into `processed/` using `shutil.move`.
- Keep the same filename in the destination.
- If a file fails to parse, decide whether to:
  - skip it and leave it in place, or
  - stop the whole process
- The safest default is usually to **process only successfully read files** and leave failures untouched.

### 6) Return output
- Return the combined DataFrame as `df`.

## Edge cases to handle

### Empty directory
- No `.json` files found.
- Return an empty DataFrame.

### Path does not exist
- Need to decide whether to:
  - create it, or
  - raise an error
- Since the prompt says “The path may not exist initially,” the function should probably **create the path or at least the `processed` subdirectory as needed** if the input directory is intended to exist. If the whole base directory is missing, creating it is reasonable.

### Non-JSON files present
- Ignore them.

### Nested directories
- Ignore subdirectories, even if they contain `.json` files, unless otherwise specified.

### Invalid JSON
- If a file contains malformed JSON, it should be handled gracefully.
- Recommended: skip the file, do not move it, and continue processing others.

### JSON structure variability
Possible JSON shapes:
- a single object/dict
- a list of objects
- scalar or nested structures

This matters because:
- `pd.DataFrame(dict)` and `pd.DataFrame(list_of_dicts)` behave differently.
- If the JSON is a single object, it likely becomes a single-row DataFrame.
- If it is a list of records, it becomes multiple rows.
- If it is not tabular, conversion may be awkward; should still attempt a DataFrame conversion and let pandas handle it.

### Duplicate filenames in different directories
- Not relevant if only one directory is processed.
- Moving preserves filename, so destination conflicts may occur only if the same name already exists in `processed/`.

### Destination file already exists
- `shutil.move` may overwrite or fail depending on platform and conditions.
- Need a policy:
  - overwrite existing file,
  - rename,
  - or raise an error.
- Most robust is to detect collision and handle it explicitly.

### File permission / access issues
- Reading or moving may fail due to permissions.
- Should ideally fail clearly or skip problematic files with a message.

### Order consistency
- Ensure alphabetical order is based on filenames, not full paths.
