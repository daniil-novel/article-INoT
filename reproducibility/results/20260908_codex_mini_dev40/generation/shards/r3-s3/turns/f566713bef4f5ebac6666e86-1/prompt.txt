## Goal
Create a function that:

1. Validates the input bases.
2. Converts `num` from `from_base` to `to_base`.
3. Adds a random salt.
4. Computes a SHA-256 hash of the salted converted value.
5. Encodes the hash in base64 using a custom alphabet.
6. Returns a tuple: `(encoded_hash, salt)`.

---

## Planned behavior

### 1) Input validation
- Raise `ValueError` if `from_base < 2` or `to_base < 2`.
- Validate that `num` is a valid representation in `from_base`.
  - For example, `'FF'` is valid in base 16.
  - `'19'` would be invalid in base 8.
- Likely also validate the custom `alphabet`:
  - It should contain exactly 64 characters for base64 encoding.
  - Ideally characters should be unique to avoid ambiguous encoding.

---

### 2) Base conversion
- Convert `num` from string form in `from_base` into an integer.
- Then convert that integer into a string representation in `to_base`.
- Handle common edge cases:
  - Leading zeros in `num` should not affect numeric value.
  - `num == '0'` should remain zero after conversion.
  - For bases above 10, use digits and letters appropriately.

---

### 3) Salt generation
- Generate a cryptographically secure random salt using `secrets`.
- The salt should be different for each call.
- Return the actual salt used so the caller can inspect or reuse it.

This is what ensures:
```python
result1, salt1 = task_func('FF', 16, 8, alphabet)
result2, salt2 = task_func('FF', 16, 8, alphabet)
result1 != result2
```
because the salt changes every time.

---

### 4) Hashing
- Build the salted payload from:
  - the converted number, and
  - the generated salt.
- Hash the payload using `hashlib.sha256`.
- Use a stable string encoding like UTF-8 before hashing.

---

### 5) Base64 encoding with custom alphabet
- Compute standard base64 from the SHA-256 digest bytes.
- Replace the standard base64 alphabet with the provided custom alphabet.
- Preserve padding if standard base64 produces it.
- If the custom alphabet is invalid or the wrong length, it should ideally raise `ValueError`.

---

## Expected return value
Return:
```python
(encoded_hash, salt)
```
where:
- `encoded_hash` is the custom-base64-encoded SHA-256 digest,
- `salt` is the random salt used in hashing.

## Edge cases to account for

### Invalid bases
- `from_base < 2`
- `to_base < 2`

### Invalid number format
- Characters in `num` not allowed by `from_base`
  - e.g. `'G'` in base 16, `'2'` in base 2

### Degenerate numeric inputs
- `num = '0'`
- `num` with leading zeros, like `'000FF'`

### Custom alphabet issues
- Alphabet length not equal to 64
- Duplicate characters in alphabet
- Non-string or empty alphabet

### Salt-related behavior
- Results must differ across invocations due to randomness
- Salt should be returned exactly as used

### Large values
- Very long input numbers should still work, since Python integers are arbitrary precision
