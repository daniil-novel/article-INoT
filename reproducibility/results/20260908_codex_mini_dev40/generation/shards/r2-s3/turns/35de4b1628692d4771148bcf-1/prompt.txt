## Goal
Process all JSON files in a directory, in alphabetical order, into a single `pandas.DataFrame`, add a `Source` column with the originating filename, and then move each processed file into a `processed` subdirectory. The directory may not exist initially.

## Expected behavior
- Input: `path` to a directory containing JSON files.
- For each `*.json` file in that directory:
  1. Read the file.
  2. Convert its JSON content into a DataFrame.
  3. Add a `Source` column with the filename.
  4. Collect the result for concatenation.
  5. Move the file to `path/processed/`.
- Output: one combined `pandas.DataFrame` containing data from all processed files.

## Implementation plan

### 1. Prepare directories
- Verify the input `path` exists.
- If it does not exist, create it.
- Create the subdirectory `processed` inside `path` if it does not already exist.

### 2. Find JSON files
- List files in `path`.
- Select only files ending with `.json`.
- Sort them alphabetically to satisfy the processing order requirement.

### 3. Read and transform each file
For each JSON file:
- Build the full file path.
- Open and parse the JSON.
- Convert the JSON data into a DataFrame.
- Add a new column:
  - `Source = filename`
- Store the resulting DataFrame in a list for later concatenation.

### 4. Move processed files
- After successfully reading and converting a file, move it to the `processed` subdirectory.
- This ensures processed files are separated from unprocessed ones.

### 5. Combine results
- If one or more files were processed:
  - Concatenate all collected DataFrames into a single DataFrame.
- If no JSON files were found:
  - Return an empty DataFrame.

## Edge cases to handle

### Directory does not exist
- Create the directory automatically rather than failing.

### No JSON files in directory
- Return an empty DataFrame.

### Empty JSON file
- `json.load` may fail; this should be handled gracefully depending on desired robustness.
- A safe choice is to skip invalid files or treat them as errors.

### Invalid JSON content
- If a file cannot be parsed as JSON, it should not break the whole function unless strict failure is desired.
- A robust implementation may skip invalid files and continue processing others.

### JSON structure variations
Different JSON files may have different structures:
- **Dictionary object**: can be converted into a one-row DataFrame.
- **List of dictionaries**: becomes multiple rows.
- **Nested structures**: may require pandas normalization if flattening is needed; otherwise they will remain as nested objects in cells.

### Mixed columns across files
- Some files may contain different fields.
- Concatenation should allow missing values where a field is absent in some files.

### File move conflicts
- If a file with the same name already exists in `processed`, decide whether to overwrite or rename.
- A practical implementation can overwrite or use `shutil.move` behavior as-is, but this should be considered.

### Permission / filesystem issues
- Directory creation, reading, or moving may fail due to permissions.
- A robust solution should either propagate the exception or handle it explicitly.
