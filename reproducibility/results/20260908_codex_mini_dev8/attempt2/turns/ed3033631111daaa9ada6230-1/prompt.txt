## Goal
The function should:

1. Download a ZIP file from `url`
2. Save it locally to `save_path`
3. Extract its contents to `extract_path`
4. Delete the downloaded ZIP file afterward
5. Return the extraction directory path on success
6. Return descriptive error strings on failure, with special handling for `urllib.error.URLError`

---

## Planned behavior

### Success path
1. Download the file from the provided URL.
2. Write it to `save_path`.
3. Verify it is a valid ZIP archive.
4. Create `extract_path` if it does not exist.
5. Extract all contents into `extract_path`.
6. Delete the ZIP file from disk.
7. Return `extract_path`.

---

## Error handling plan

### 1) URL / network failures
Catch `urllib.error.URLError` and return:

```python
f"URL Error: {reason}"
```

Where `reason` should be taken from the exception if available.

This covers:
- malformed or invalid URL
- unreachable server
- DNS/network failures

---

### 2) Corrupted or invalid ZIP file
After download, validate the file before extraction.

Handle:
- `zipfile.BadZipFile`
- `zipfile.LargeZipFile` if relevant
- `zipfile.is_zipfile(save_path)` returning `False`

Return a descriptive message such as:
- `"ZIP Error: downloaded file is not a valid ZIP archive"`
- `"ZIP Error: corrupted ZIP file"`

---

### 3) File I/O failures
Catch `OSError` / `IOError` for:
- permission denied
- disk full
- invalid path
- inability to create extraction directory
- inability to delete the ZIP file

Return messages like:
- `"File Error: [details]"`

---

### 4) Unexpected errors
Catch any other exception as a fallback and return:
- `"Unexpected Error: [details]"`

This helps ensure the function always returns a useful string instead of crashing unexpectedly.

---

## Cleanup plan
Use a `finally` block or equivalent cleanup logic to delete the downloaded ZIP file if it exists, even if extraction fails.

Important nuance:
- If download fails before the file exists, cleanup should not fail.
- If extraction succeeds but deletion fails, the function should still return an error message indicating cleanup failure if needed.

---

## Edge cases to account for

### URL-related
- URL has no scheme, e.g. `"example.com/file.zip"`
- URL points to a 404/503 or unreachable host
- Redirects or other server-side issues

### ZIP-related
- File downloads successfully but is HTML or plain text instead of ZIP
- ZIP file is partially downloaded or corrupted
- ZIP contains nested folders, empty files, or unusual filenames
- ZIP is password-protected or otherwise not extractable normally

### Filesystem-related
- `extract_path` does not exist and must be created
- `save_path` points to a directory by mistake
- No permission to write to `save_path`
- No permission to create or write into `extract_path`
- Existing file at `save_path` should be overwritten or safely replaced
- Cleanup delete fails because file is locked

### Platform/path issues
- Windows path separators
- Relative paths vs absolute paths
- Unicode or special characters in paths
