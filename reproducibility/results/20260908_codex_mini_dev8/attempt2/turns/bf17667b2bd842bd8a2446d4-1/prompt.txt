## Goal
Implement a function that:

1. Takes a filename.
2. Copies that file from a predefined source directory to a backup directory.
3. Executes the copied file as a subprocess.
4. Returns:
   - the subprocess exit code on success
   - `-1` if the backup step fails

---

## Planned behavior

### 1) Build source and destination paths
- Source file path: join `DIRECTORY` and `filename`
- Backup file path: join `BACKUP_DIRECTORY` and `filename`

Use `os.path.join(...)` to avoid hardcoding separators.

---

### 2) Validate input
Check that:
- `filename` is not empty
- `filename` does not attempt path traversal like:
  - `..\\otherfile.exe`
  - absolute paths like `C:\Windows\...`
- optional: reject directory-like input

This helps ensure the function only works on files inside `DIRECTORY`.

---

### 3) Verify source file exists
Before copying:
- confirm the source path exists
- confirm it is a file, not a directory

If missing or invalid, treat this as backup failure and return `-1`.

---

### 4) Ensure backup directory exists
Before copying:
- create `BACKUP_DIRECTORY` if it does not already exist

Use something like `os.makedirs(..., exist_ok=True)`.

If directory creation fails, return `-1`.

---

### 5) Copy file to backup directory
Use `shutil.copy2(...)` or `shutil.copy(...)`.

Prefer `copy2` because it preserves metadata if possible.

If copy fails for any reason:
- permission error
- file locked
- disk full
- invalid filename
- source unreadable

Return `-1`.

---

### 6) Execute the copied file as a subprocess
After a successful copy:
- run the backup copy using `subprocess.run(...)`
- use the copied file path as the executable/command

Return its exit code:
- `result.returncode`

Depending on file type, the exact subprocess call may need adjustment:
- if it is an executable: run directly
- if it is a script: may need `sys.executable` or another interpreter
- if the file is not executable, subprocess invocation may fail

---

### 7) Handle subprocess execution failures
If subprocess execution itself fails:
- command not found
- invalid executable
- permission denied
- launch failure

The prompt only explicitly says `-1` for backup failure, but it is safest to also return `-1` for subprocess launch errors unless a different behavior is required.

---

## Edge cases to handle

### Filename issues
- empty string
- `None`
- non-string input
- path traversal attempts
- absolute paths
- filenames containing path separators

### Source file issues
- source file does not exist
- source path points to a directory
- source file inaccessible due to permissions
- source file locked by another process

### Backup directory issues
- backup directory missing
- cannot create backup directory
- backup path not writable
- name collision with existing file

### Copy issues
- insufficient disk space
- I/O errors
- antivirus or file locking interference

### Subprocess issues
- copied file is not executable
- file type requires interpreter
- process fails at startup
- process returns non-zero exit code

---

## Suggested control flow
1. Validate `filename`
2. Construct source and backup paths
3. Ensure source exists and is a file
4. Create backup directory if needed
5. Copy source to backup
6. Execute backup copy as subprocess
7. Return subprocess exit code
8. On any backup-related failure, return `-1`
