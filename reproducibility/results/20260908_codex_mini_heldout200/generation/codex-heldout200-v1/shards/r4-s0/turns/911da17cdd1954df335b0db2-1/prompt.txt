Because a paired t-test requires two equal-length numeric samples, the most reasonable interpretation is:

- Split each input string into words.
- Convert each word into a numeric value, most naturally its **length**.
- Run `ttest_rel` on the two sequences of word lengths.
- Only do this if both strings contain the **same number of words**.
- Otherwise return `(np.nan, np.nan)`.

## Edge cases to handle
- **Unequal word counts**
  - Must return `(np.nan, np.nan)`.

- **Empty strings**
  - Both empty: same length, but no words; t-test is not meaningful.
  - One empty, one non-empty: unequal lengths → `(np.nan, np.nan)`.

- **Single-word strings**
  - Equal lengths but only one paired observation.
  - The t-test is statistically undefined or uninformative; safest behavior is to return SciPy’s result, which may be `nan`, or explicitly guard and return `(np.nan, np.nan)`.

- **Strings with punctuation**
  - Tokenization should ignore punctuation so `"hello, world!"` becomes two words.

- **Multiple spaces / tabs / newlines**
  - Regex tokenization handles these naturally.

- **Non-ASCII text**
  - Use a regex approach that is reasonably robust for general Unicode word characters if needed.

- **Zero variance in paired differences**
  - If all paired word lengths are identical, the t-test may return `nan` due to numerical/variance issues; this is acceptable unless the task specifies otherwise.

## Suggested behavior summary
- Same number of words → compute paired t-test on word lengths.
- Different number of words → return `(np.nan, np.nan)`.
