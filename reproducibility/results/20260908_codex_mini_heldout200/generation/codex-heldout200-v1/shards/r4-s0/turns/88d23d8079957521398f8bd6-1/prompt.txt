## Edge cases to handle

### 1. `hours = 0`
- Should not fail.
- CSV should still be created, probably with headers only.
- Plot may be empty but valid.

### 2. Negative `hours`
- Invalid input.
- Raise `ValueError`.

### 3. Non-integer input
- Examples: `"5"`, `3.2`, `None`
- Either:
  - reject with `TypeError`/`ValueError`, or
  - safely coerce integers if that’s intended
- Best practice: explicitly validate to avoid silent mistakes.

### 4. Very large `hours`
- Could create a large CSV and cluttered plot.
- The function should still work, but plotting may become unreadable.
- Optional improvement: rotate labels and/or reduce tick density.

### 5. File path issues
- If `file_path` points to a non-writable location, CSV writing will fail.
- Since no error handling is specified, allow exceptions to propagate naturally.

### 6. Randomness
- Data will differ on each run because `randint` is used.
- If reproducibility is needed later, a seed would be required, but it is not part of the current requirements.
