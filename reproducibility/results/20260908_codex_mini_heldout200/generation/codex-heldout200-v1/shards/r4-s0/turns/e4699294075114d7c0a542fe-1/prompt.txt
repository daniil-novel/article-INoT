## Goal
Clean a string by removing special characters and punctuation with regex, tokenize it, and return a dictionary of word frequencies.

## Important requirement note
There is a small conflict in the task wording:

- If you **remove spaces before tokenizing**, all words get merged into one string, so word counting becomes impossible.
- To count words correctly, spaces must be preserved until tokenization.

So the practical implementation should:
1. remove punctuation/special characters with regex,
2. tokenize into words,
3. count frequencies,
4. return a dictionary.

## Plan

### 1. Validate input
- If `input_str` is `None` or not a string, handle safely.
- If the string is empty or contains only removed characters, return `{}`.

### 2. Normalize text
- Convert to lowercase so `"Word"` and `"word"` are counted together.
- This is usually expected for frequency counts unless case sensitivity is required.

### 3. Clean the text using regex
- Use a regex replacement to remove special characters and punctuation.
- Keep letters, digits, and whitespace during this step so tokenization still works.

Example cleaning idea:
- Replace anything that is not a word character or whitespace with nothing.

### 4. Tokenize the cleaned text
- Use `word_tokenize` on the cleaned string.
- Filter out any empty tokens or tokens that are just whitespace.

### 5. Count frequencies
- Use `Counter` to count each token.

### 6. Return output
- Return `dict(Counter(...))`, since the task asks for a dictionary.

## Edge cases to handle

### Empty or blank input
- `""`, `"   "` → return `{}`

### Only punctuation/special characters
- `"!!!@@@###"` → after cleaning, no words remain, so return `{}`

### Multiple spaces
- `"hello   world"` should still count as `{"hello": 1, "world": 1}`

### Mixed case
- `"Apple apple APPLE"` should count as one word if lowercased first

### Numbers
- Decide whether numbers should count as words.
- If yes, keep them in the regex cleaning.
- Example: `"abc 123"` → `{"abc": 1, "123": 1}`

### Hyphenated or apostrophe words
- `"state-of-the-art"` and `"don't"` need a policy:
  - either split them into separate tokens,
  - or normalize them by removing punctuation.
- The simplest approach is to strip punctuation and let tokenization split them.

### Unicode / non-English text
- If the input may contain accented or non-Latin characters, use a regex strategy that preserves Unicode word characters if possible.

### NLTK resource availability
- `word_tokenize` may require NLTK tokenizer data to be available.
- The function should assume the environment is prepared, or fall back gracefully if not.
