- Open the target file with `newline=""` and UTF-8 encoding.

## Important edge cases

### Excel format support
- `openpyxl` supports **.xlsx/.xlsm**, but **not legacy .xls**.
- Since the task mentions `.xls or .xlsx`, you should decide one of these:
  1. **Strict support for openpyxl-compatible files only**, and raise a clear error for `.xls`.
  2. Add a separate reader for `.xls` if available in the environment.
- Because the provided imports only include `openpyxl`, the safest plan is to:
  - support `.xlsx`/`.xlsm`
  - fail clearly for `.xls`

### Empty workbook / empty sheet
- If the active sheet has no data, create an empty CSV file.
- Still return the output filename.

### Formula cells
- With `data_only=True`, formula results are written if cached values exist.
- If not, cells may appear empty.

### Missing destination directory
- If the destination directory does not exist, either:
  - create it, or
  - raise an informative exception.
- A robust implementation would create it.

### Overwriting existing CSV
- Decide whether to overwrite silently or prevent overwrite.
- The simplest behavior is overwrite.

### File name/path ambiguity
- The signature includes both `file_name` and `csv_file_path`, so the intended meaning may be ambiguous.
- A practical rule:
  - `file_name` controls the output CSV name
  - `csv_file_path` controls the destination folder or full target path

### Non-string cell values
- Excel cells can contain numbers, booleans, dates, and `None`.
- `csv.writer` can handle most values, but `None` should usually be converted to `""` for cleaner CSV output.

### Special characters / commas / quotes / newlines
- Let `csv.writer` handle quoting automatically.
- This avoids malformed CSV when cell values contain commas or line breaks.
