## Edge cases to handle

### 1. Empty DataFrame
- If `df` has no rows, regression cannot be fit.
- Return a sensible fallback or raise a clear error.
- Since the expected output is a tuple with predictions and axes, a safe fallback could be:
  - 7 `NaN` predictions
  - an axes object with an explanatory message
- If strict behavior is preferred, raise `ValueError`.

### 2. Missing required columns
- If the closing price column is missing, the function should fail clearly.
- Same for missing date/time information.

### 3. Non-datetime timestamps
- If the time column is string-based, parse it using `pd.to_datetime`.
- If parsing fails, raise an informative error.

### 4. Unsorted input
- The input may not be ordered by date.
- Sort by timestamp before fitting and plotting.

### 5. Too few rows
- Linear regression technically needs at least 2 points.
- If there is only 1 data point:
  - a meaningful trend cannot be learned
  - either raise an error or return repeated values based on the single observed price

### 6. Missing values
- Drop rows where timestamp or close price is missing.
- If too many values are missing and not enough remain, handle as insufficient data.

### 7. Duplicate timestamps
- Duplicate dates may cause ambiguous fitting.
- Decide whether to:
  - keep them as-is,
  - average them,
  - or drop duplicates.
- For a clean regression fit, aggregating or deduplicating may be preferable.

### 8. Constant prices
- If all closing prices are identical, the regression slope will be ~0.
- This is valid; predictions should be near the constant value.

### 9. Large timestamp values
- Unix timestamps can be large numbers.
- Linear regression can still work, but numerical stability may improve if timestamps are centered or converted to relative days.
- Since the task explicitly wants future timestamps generated in seconds, using seconds is acceptable.
