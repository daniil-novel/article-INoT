### Requirements analysis

Implement `task_func(process_name: str) -> int` to:

- find all running processes whose **name matches** `process_name`
- send them a **termination signal**
- wait **1 second**
- return the **number of processes stopped/targeted**
- return `0` when no matching processes exist

Given the allowed imports, the implementation should rely on `subprocess`, `os`, `signal`, and `time` only.

---

### Implementation plan

1. **Validate input**
   - If `process_name` is empty or only whitespace, return `0`.
   - Keep the provided name unchanged for matching, but use a normalized form if needed for platform comparison.

2. **Detect platform behavior**
   - Use `os.name` / platform-specific handling:
     - **POSIX**: can use `ps` to enumerate processes, then `os.kill(pid, signal.SIGTERM)`.
     - **Windows**: process names are typically case-insensitive and often include `.exe`; matching should account for that.

3. **Enumerate running processes**
   - Use `subprocess.check_output(...)` or similar to get a process list.
   - Parse the output to extract:
     - PID
     - executable/process name
   - Avoid `shell=True` if possible.

4. **Match processes by name**
   - Compare the running process name against `process_name`.
   - On Windows, compare case-insensitively.
   - On Windows, if the caller passes `notepad`, optionally also match `notepad.exe` if that is how the process appears.
   - Match the **process name only**, not partial substrings, to avoid stopping unrelated processes.

5. **Send termination signal**
   - For each matched PID:
     - call `os.kill(pid, signal.SIGTERM)`
     - if the process is already gone, ignore `ProcessLookupError`
     - if permission is denied, ignore or skip that PID
   - Count only processes for which the termination signal was successfully issued.

6. **Wait briefly**
   - Call `time.sleep(1)` after issuing signals.
   - Do not assume every process has exited by then; the task explicitly says there is no guarantee.

7. **Return the count**
   - Return the number of matched processes that were signaled.

---

### Edge cases to handle

- **No matches found**  
  Return `0`.

- **Empty/blank `process_name`**  
  Return `0` immediately.

- **Case sensitivity**
  - Windows: compare case-insensitively.
  - POSIX: compare exactly unless the process-listing API normalizes differently.

- **Windows executable extension**
  - Matching `chrome` vs `chrome.exe` may matter.

- **Race condition**
  - A process may exit after enumeration but before signaling.
  - Handle `ProcessLookupError` gracefully.

- **Permission issues**
  - Some processes may not be killable by the current user.
  - Skip those without crashing.

- **Multiple instances**
  - All matching processes should be targeted, not just the first one.

- **Self-termination risk**
  - If the target name matches the current interpreter/process, the function could kill itself before returning.
  - This should be considered carefully; if needed, exclude the current PID only if that is acceptable for the intended behavior.

- **Parsing robustness**
  - Process-list output may contain headers, variable spacing, or quoted values.
  - Parsing should be resilient and not rely on fragile string splits if avoidable.

---

### Recommended behavior choice

Because the note says termination is not guaranteed within 1 second, the most practical interpretation is:

- **count processes that were matched and sent a termination signal**
- do **not** require confirmation that they fully exited within the wait window

That gives a stable and testable return value.
