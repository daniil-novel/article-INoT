## Requirements analysis

You need a function `task_func(directory)` that:

- creates a backup of the given directory
- cleans the original directory afterward
- returns a tuple:
  - `str`: the backup directory path
  - `list`: errors encountered during the operation, or an empty list if none

The supplied scaffold strongly suggests:

- `BACKUP_DIR = '/tmp/backup'` is the base backup location
- `get_unique_backup_dir()` should produce a unique destination path under the backup root
- the final code should be self-contained and start with the provided imports/constants/function names

## Implementation plan

### 1) Validate input
- Check that `directory` is a valid path-like string.
- Verify it exists and is a directory.
- If invalid, return a backup path value if appropriate and add an error message; otherwise decide on a safe fallback behavior.

### 2) Create a unique backup path
- Use `get_unique_backup_dir()` to get a destination directory path.
- Ensure the backup target does not collide with an existing backup.
- Create the backup directory structure if needed.

### 3) Copy the directory contents
- Copy the source directory into the backup directory.
- Preserve files, subdirectories, and metadata as much as practical.
- Prefer `shutil.copytree` or an equivalent recursive copy approach.
- Collect any copy-related exceptions into the errors list.

### 4) Clean the original directory
- If backup succeeds, remove the original directory contents.
- Decide whether to:
  - remove only contents and keep the directory itself, or
  - remove the directory and recreate it
- The safer default is usually to keep the directory and delete its contents.
- Continue deleting remaining items even if some removals fail, and record each error.

### 5) Return the result
- Return `(backup_dir_path, errors)`
- If no issues occurred, `errors` should be `[]`

---

## Edge cases to handle

### Input/path issues
- `directory` does not exist
- `directory` is not a directory
- `directory` is empty
- path is unreadable or inaccessible due to permissions

### Backup creation issues
- backup root `/tmp/backup` does not exist
- backup root cannot be created
- destination path already exists
- filesystem errors during copy
- files are locked or in use

### Cleanup issues
- some files cannot be deleted due to permissions
- read-only files
- nested subdirectories fail to remove
- cleanup partially succeeds

### Special file types
- symbolic links
- sockets, FIFOs, device files
- very deep directory trees
- large files

### Consistency concerns
- source changes while backup is in progress
- backup succeeds but cleanup fails
- cleanup starts only after a successful backup
- partial failures should be reported, not silently ignored

---

## Error-handling strategy

- Use a list of human-readable error strings.
- Catch exceptions around:
  - backup directory creation
  - recursive copy
  - file removal
  - directory removal
- Prefer continuing cleanup after individual file errors, so one bad file does not stop the whole operation.
- Do not let a single failure crash the function unless the backup itself cannot be created at all.

---

## Recommended behavior

A practical and robust flow is:

1. Validate source directory
2. Compute unique backup path
3. Copy source to backup
4. If copy succeeds, delete contents of source directory
5. Return backup path and accumulated errors
