## Edge cases to handle

### A) Comma-formatted numbers
- Values like `"3,14"` should be converted to `3.14`.
- Be careful not to break already valid numbers.

### B) Missing or invalid values
- If a cell cannot be parsed as a number, convert it to `NaN`.
- Means/std devs should ignore `NaN`.
- Histograms should use only valid numeric values.

### C) Columns with all invalid values
- A column may become entirely `NaN` after conversion.
- In that case:
  - mean and std dev will be `NaN`,
  - histogram will be empty or should be handled gracefully,
  - ANOVA involving that column should either be skipped or return `NaN` results.

### D) Too few valid observations for ANOVA
- ANOVA requires enough data in each group.
- If a pair has no valid observations or only one valid point in a group, return `NaN` for F and P or skip safely.

### E) Constant columns
- If a column has zero variance, ANOVA may produce warnings or degenerate results.
- Handle without crashing; return whatever the statistical function yields, or `NaN` if it fails.

### F) One numerical column only
- Still compute mean, std dev, and histogram.
- Return an empty ANOVA DataFrame.

### G) Empty CSV
- If the file has no usable rows/columns, return empty or all-`NaN` outputs consistently and avoid plotting failures.
