## Important edge cases to handle

### 2) Already numeric values
- If a column is already numeric, conversion should not break it.

### 3) Mixed invalid entries
- If some entries are not parseable, convert them to `NaN` rather than failing.

### 4) Missing values
- Mean and standard deviation should ignore `NaN` by default.
- Histograms should be created using non-missing values only.
- ANOVA should exclude `NaN` values before testing.

### 5) One numeric column only
- `anova_results` should be empty or not populated with tests, since ANOVA requires at least two groups.

### 6) No numeric columns after conversion
- Return empty `means`, empty `std_devs`, empty `axes`, and an empty `anova_results` DataFrame.

### 7) Columns with too few valid values for ANOVA
- If a column has fewer than 2 valid observations, pairwise ANOVA may be invalid or meaningless.
- Such pairs should be skipped or handled safely.

### 8) Identical columns / zero variance
- ANOVA may produce unstable or undefined results if one or both groups have no variance.
- The function should still avoid crashing and return a result if the library allows it.

### 9) Pairwise ANOVA definition
- The task explicitly asks for ANOVA results “for each pair of numerical columns.”
- So the output should be pairwise, not one global ANOVA across all columns.
