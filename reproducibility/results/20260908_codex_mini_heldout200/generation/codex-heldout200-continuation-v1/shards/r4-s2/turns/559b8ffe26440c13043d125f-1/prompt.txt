## Goal
Return the number of **whole seconds** from the given date/time to the **next New Year’s moment** (`Jan 1, 00:00:00`) in the specified time zone.

---

## Planned approach

### 1) Parse the input date string
- Use `dateutil.parser.parse(date_str)` to convert the input string into a `datetime`.
- This supports many common date formats.

### 2) Resolve the target time zone
- Use `pytz.timezone(tz_str)` to get the time zone object.
- If `tz_str` is invalid, the function should naturally raise the corresponding exception.

### 3) Normalize the input datetime to the specified time zone
Handle both cases:

- **Naive datetime** (`dt.tzinfo is None`):
  - Interpret it as being in the given time zone.
  - Localize it with `tz.localize(dt)`.

- **Timezone-aware datetime**:
  - Convert it into the requested time zone using `astimezone(tz)`.

This ensures the “current date” is interpreted consistently in the specified zone.

### 4) Compute the next New Year moment in that time zone
- Let `year = current_dt.year + 1`.
- Build the target datetime as:
  - `datetime(year, 1, 1, 0, 0, 0)`
- Localize that datetime to the same timezone.

This represents the next turn of the year after the given moment.

### 5) Calculate the difference in seconds
- Compute:
  - `target_dt - current_dt`
- Convert the result to seconds with:
  - `int(delta.total_seconds())`

Return that integer.

## Edge cases to handle

### 1) Input exactly at New Year
Example: `2026-01-01 00:00:00`
- The “next” New Year should be **2027-01-01 00:00:00**.
- So the function must always move to the **next calendar year**, not the current one.

### 2) Dates on December 31 near midnight
- Example: `2025-12-31 23:59:59`
- Result should be `1`.

### 3) Time zone-aware input strings
- If the input date string already includes an offset or timezone, it should be converted to the requested timezone before calculation.

### 4) Daylight saving time / time zone transitions
- The target is midnight on January 1 in the requested zone.
- Usually this is safe, but localization should be done with `pytz.localize()` to avoid incorrect fixed offsets.

### 5) Invalid input format
- If the date string cannot be parsed, `parse()` will raise an exception.
- If the time zone is invalid, `pytz.timezone()` will raise an exception.
- No special recovery is required unless explicitly desired.

### 6) Leap years
- No special handling needed.
- The next New Year is always January 1 of the next year.

### 7) Negative results
- Should not happen if we always compute the next Jan 1 in the same timezone using `current_dt.year + 1`.
