### Goal
Fetch an image from a direct URL and return it as a `PIL.Image.Image` object.

### Required behavior
- Use `requests` to download the content.
- Use a **5-second timeout** for the HTTP request.
- Do **not** support redirects/authentication workflows beyond a direct image URL.
- Raise `ValueError` if:
  - the URL is invalid,
  - the request times out or cannot be reached,
  - the HTTP response is not successful (`status_code` not in `200-299`),
  - the downloaded content is not a valid image that PIL can open.

## Planned implementation steps

1. **Send HTTP GET request**
   - Call `requests.get(url, timeout=5)`.
   - Do not enable special redirect/auth handling.
   - Treat any request failure as a `ValueError`.

2. **Validate HTTP success**
   - Check the response status.
   - If status is not successful, raise `ValueError`.

3. **Convert response bytes to in-memory file**
   - Use `io.BytesIO(response.content)` to wrap the downloaded bytes.

4. **Open image with PIL**
   - Use `Image.open(...)` on the `BytesIO` object.
   - Call `.load()` to force full decoding immediately, so invalid image data is caught inside the function rather than later.

5. **Return the image**
   - Return the resulting `PIL.Image.Image` object.

6. **Normalize all expected failures to `ValueError`**
   - Catch request-related exceptions:
     - invalid URL,
     - connection errors,
     - timeout,
     - any request-level failure.
   - Catch PIL image parsing failures:
     - invalid/corrupted/non-image content.
   - Re-raise as `ValueError` with a clear message.

## Edge cases to handle

- **Malformed URL**
  - Example: missing scheme (`example.com/img.png`) or invalid format.
  - Should raise `ValueError`.

- **Timeout**
  - Server does not respond within 5 seconds.
  - Should raise `ValueError`.

- **Network failure**
  - DNS failure, connection refused, unreachable host.
  - Should raise `ValueError`.

- **HTTP error responses**
  - 404, 403, 500, etc.
  - Should raise `ValueError`.

- **Redirects**
  - Since redirects are not to be handled, avoid relying on redirected resources.
  - If the URL does not directly serve an image, treat it as failure.

- **Non-image content**
  - HTML page, JSON, text file, or other unsupported bytes.
  - `Image.open` should fail, and this should become `ValueError`.

- **Corrupted image bytes**
  - Content may look like an image response but be incomplete or malformed.
  - Should raise `ValueError`.

- **Empty response body**
  - Should raise `ValueError` when PIL cannot decode it.
