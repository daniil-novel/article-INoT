## Requirements summary
Implement `task_func(ax)` that:

1. Works with a provided Matplotlib **polar** axis `ax`.
2. Generates and plots a **random sine wave** on that axis.
3. Randomly selects a line color from:
   `['b', 'g', 'r', 'c', 'm', 'y', 'k']`
4. Randomly sets the **radial label position**.
5. Returns the chosen color as a `str`.

## Proposed implementation plan
1. **Choose a random color**
   - Use `random.choice(COLORS)`.

2. **Generate polar x-values**
   - Create a theta array spanning a full circle, e.g. `0` to `2π`.
   - Use enough points for a smooth curve.

3. **Generate a random sine wave**
   - Build a radial function like:
     - random amplitude
     - random frequency
     - random phase shift
     - optional vertical offset so the radius stays mostly positive
   - Example shape conceptually: `r = offset + amp * np.sin(freq * theta + phase)`

4. **Plot on the polar axis**
   - Call `ax.plot(theta, r, color=chosen_color)`.

5. **Randomize radial label position**
   - Use `ax.set_rlabel_position(...)` with a random angle, typically an integer in `[0, 360)`.

6. **Return the color string**
   - Return the selected color code exactly.

## Edge cases to consider
- **`ax` is not a polar axis**
  - The function assumes the caller provides a polar subplot.
  - If not, plotting may still run, but the output won’t be correct. Optional defensive check could be added, but the task does not require it.

- **Negative radii**
  - Pure sine waves can go negative, which may be visually awkward on polar plots.
  - Using a positive offset helps keep the curve meaningful.

- **Empty `COLORS` list**
  - Not expected here because it is predefined.
  - If someone modifies it later, `random.choice` would fail.

- **Reproducibility**
  - The plot is intentionally random.
  - If deterministic output is needed in the future, seed `random` and NumPy.

- **Return type**
  - Must return only the color code string, not the plotted line object.
