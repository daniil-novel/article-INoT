### Requirements analysis

We need implement `task_func(data_dict: dict, seed=0) -> dict` that:

1. Adds key `"a"` with value `1`.
2. Generates a random salt of length `5` using lowercase ASCII letters.
3. For every existing key-value pair in the dictionary, concatenate the value with the salt, compute SHA-256 of that string, and replace the value with the hex digest.
4. Add a key `"timestamp"` with the current UNIX timestamp.

### Important interpretation details

- The newly added `"a": 1` should be included in the hashing step, because it is added before step 3.
- The `"timestamp"` key should be added after hashing, so it should **not** be hashed.
- The salt should be reproducible if `seed` is provided, so use a seeded random generator rather than the global random state.
- Since dictionary values may not be strings, convert values to `str` before concatenation with the salt.

### Suggested implementation plan

1. **Create or copy the input dictionary**
   - To avoid unexpected side effects, work on a copy of `data_dict`.

2. **Add `"a": 1`**
   - Set `data_dict["a"] = 1`.

3. **Generate salt**
   - Use a seeded random generator: `rng = random.Random(seed)`.
   - Build a 5-character salt from `string.ascii_lowercase`.

4. **Hash all current items**
   - Iterate over a snapshot of `data_dict.items()` to avoid mutation issues.
   - For each `(key, value)`:
     - Convert `value` to string.
     - Concatenate `str(value) + salt`.
     - Compute SHA-256 hash.
     - Replace the value in the dictionary with the hex digest.

5. **Add timestamp**
   - Set `data_dict["timestamp"] = int(time.time())`.

6. **Return the processed dictionary**

### Edge cases to consider

- **Empty input dictionary**
  - Should still produce `{"a": <hashed>, "timestamp": ...}`.

- **Existing `"a"` key**
  - It should be overwritten by `1` as required.

- **Non-string values**
  - Integers, floats, booleans, lists, etc. must be converted with `str(...)` before hashing.

- **Dictionary mutation during iteration**
  - Must iterate over a copied list of items, not the live dictionary view.

- **Timestamp precision**
  - “Current UNIX timestamp” usually means integer seconds; use `int(time.time())`.

- **Deterministic salt generation**
  - If tests rely on repeatability, `seed` should control the salt generation.

- **Order of operations**
  - Hashing must happen before adding `"timestamp"` so timestamp is left unhashed.
