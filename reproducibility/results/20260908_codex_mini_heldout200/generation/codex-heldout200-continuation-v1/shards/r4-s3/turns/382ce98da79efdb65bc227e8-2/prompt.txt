## Edge cases to handle

1. **Non-serializable data**
   - Example: sets, custom objects, or other unsupported types.
   - `json.dumps` will raise `TypeError`.

2. **Invalid file path / write permission error**
   - Example: directory does not exist, file cannot be created, or permission is denied.
   - Opening the file can raise `OSError` / `IOError`.

3. **File exists but readback fails**
   - The write may succeed, but reading may fail due to filesystem issues.
   - Handle read errors separately.

4. **Empty dictionary**
   - `{}` is valid JSON and should still be written and verified.

5. **Nested dictionaries / lists / numbers / strings**
   - These are valid JSON values and should serialize correctly.

6. **Overwrite behavior**
   - Opening with `"w"` truncates existing content.
   - This is expected unless you want append behavior, which would not be correct for JSON objects.

7. **Unicode characters**
   - Use UTF-8 encoding to preserve non-ASCII text.

8. **Verification mismatch**
   - The read-back content should match what was written.
   - If using `json.dumps` with default formatting, read-back as raw text should match exactly.
   - If comparing objects, use `json.loads(read_content) == data`.

import json
import os

def task_func(filename, data):
    try:
        written_data = json.dumps(data, ensure_ascii=False)
        
        with open(filename, "w", encoding="utf-8") as file:
            file.write(written_data)

        if not os.path.exists(filename):
            return False, ""

        with open(filename, "r", encoding="utf-8") as file:
            read_data = file.read()

        if json.loads(read_data) != data:
            return False, read_data

        return True, read_data
    except (TypeError, ValueError, OSError):
        return False, ""
