## Intended behavior

A reasonable interpretation of “randomly choosing directions at each step” is a 4-direction lattice walk:

- right: `(x + 1, y)`
- left: `(x - 1, y)`
- up: `(x, y + 1)`
- down: `(x, y - 1)`

The walk should start at the origin `(0, 0)`.

The output should be a figure containing the path as a line plot, likely with markers so the path is visible.

## Implementation plan

### 1. Validate / normalize input
- Accept `POINTS` as the number of steps.
- Convert or require it to be an integer.
- Handle non-positive values safely.

Suggested policy:
- If `POINTS <= 0`, create a plot with only the starting point `(0,0)` and return that figure.
- If `POINTS` is not an integer, either cast to `int` or raise a clear error.  
  For robustness in a standalone task, casting with `int(POINTS)` is acceptable, but if strictness is preferred, raise `TypeError`.

### 2. Initialize coordinate storage
- Create arrays of length `POINTS + 1` because the origin is included.
- Use NumPy arrays for `x` and `y`.
- Set:
  - `x[0] = 0`
  - `y[0] = 0`

### 3. Generate the random walk
For each step `i` from `1` to `POINTS`:
- Draw a random integer in `[0, 3]` using `randint(0, 3)`.
- Map the value to one direction:
  - `0 -> x += 1`
  - `1 -> x -= 1`
  - `2 -> y += 1`
  - `3 -> y -= 1`
- Store the updated coordinates in the arrays.

This produces a simple unbiased 2D random walk.

### 4. Plot the path

- Plot `x` and `y` using a line plot:
  - `ax.plot(x, y, ...)`
- Optionally mark the start and end point.

  - `ax.set_aspect("equal", adjustable="box")`
- Add labels/title/grid for readability.

### 5. Return the figure object
- Return the figure created by `plt.subplots()`.
- Do not call `plt.show()` inside the function unless explicitly required.
- The figure object should be suitable for downstream rendering or testing.
