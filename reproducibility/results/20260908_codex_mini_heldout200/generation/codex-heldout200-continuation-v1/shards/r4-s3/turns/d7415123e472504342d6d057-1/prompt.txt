## Goal
Scan all IPs in a given IPv4 range, ping each one, and return a dictionary:

- **key**: IP address as a string
- **value**: `True` if ping succeeds, `False` otherwise

The function must **raise `subprocess.CalledProcessError`** if a ping command fails due to a subprocess error.

## Planned behavior

### 1) Parse the input range
- Accept `ip_range` as something usable by `IPv4Network`:
  - likely a CIDR string such as `"192.168.1.0/24"`
  - possibly already an `IPv4Network` object
- Convert it to an `IPv4Network` instance if needed.

### 2) Iterate through all addresses in the network
- Use the network iterator to scan each IP in the specified range.
- Decide whether to include:
  - **all addresses** in the network, including network/broadcast, or
  - only **usable host addresses**
- Since the task says “specified IP address range” without clarifying, the safest interpretation is to scan **all addresses yielded by `IPv4Network` iteration** unless requirements or tests suggest otherwise.

### 3) Ping each address
- For each IP:
  - run a subprocess ping command
  - determine success from the subprocess return code
- On success, store `True`
- On failure, store `False`

### 4) Handle subprocess errors
- If `subprocess.run(..., check=True)` is used and ping fails, a `subprocess.CalledProcessError` will be raised.
- The requirement explicitly says to raise this exception for subprocess errors, so:
  - do **not** swallow it
  - let it propagate naturally
- Distinguish between:
  - **ping returned non-zero** → should likely be captured as `False` if treated as an unsuccessful ping
  - **subprocess infrastructure failure** → re-raise `CalledProcessError`

## Edge cases to consider

### Input-related
1. **Invalid IP range string**
   - Example: `"999.999.0.0/24"`
   - `IPv4Network` will raise an exception
   - Decide whether to let that propagate naturally

2. **`ip_range` already an `IPv4Network`**
   - Should be supported cleanly without reparsing

3. **Single-host network**
   - Example: `"192.168.1.5/32"`
   - Should still return one entry

4. **Very large network**
   - Example: `/8`
   - Could create a very large dictionary and take a long time
   - No special handling required unless performance constraints are mentioned

### Ping-related
5. **Host unreachable**
   - Ping should return `False`

6. **Command not found / OS differences**
   - `ping` command arguments differ between Windows and Unix-like systems
   - Since the environment appears Windows-based, use Windows-compatible ping parameters if needed
   - If portability is important, adapt command construction by platform

7. **Subprocess failure**
   - If subprocess raises `CalledProcessError`, let it propagate as required

8. **Timeouts**
   - If a ping times out but returns non-zero, mark as `False`
   - If a timeout is represented as a subprocess exception, decide whether to treat it as `False` or let it propagate based on whether it is a `CalledProcessError`
