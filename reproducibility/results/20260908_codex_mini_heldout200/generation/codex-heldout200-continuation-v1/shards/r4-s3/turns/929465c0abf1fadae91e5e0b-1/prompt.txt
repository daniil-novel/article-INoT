## Edge Cases to Handle

### 1) Empty DataFrame
- Cannot fit a model.
- Raise `ValueError("Input DataFrame is empty.")`

### 2) Missing closing-price column
- If no recognizable close column exists, raise a clear error.
- Optionally support a small set of common column names.

### 3) Non-numeric close values
- Coerce to numeric.
- Drop invalid rows.
- If too many invalid values leave too little data, raise an error.

### 4) Insufficient observations
- ARIMA may fail or produce unstable results.
- Raise a helpful error if the cleaned series is too short.

### 5) Constant series
- ARIMA can be numerically problematic with a flat series.
- The model may still fit, but if it fails, a fallback could be to repeat the last value 7 times.

### 6) Missing dates / unsorted dates
- Sort by date if possible.
- If no date column exists, keep original order.

### 7) NaNs / infinities in the data
- Clean them before fitting.
- Remove or interpolate only if appropriate; dropping is simplest.

### 8) Model convergence failure
- ARIMA fitting can fail for some datasets.
- A robust implementation can wrap fitting in `try/except` and:
  - either raise a clear error, or
  - fall back to a naive forecast using the last observed price.

### 9) Forecast plotting alignment
- Ensure the forecast x-axis extends correctly beyond the historical period.
- Avoid overlapping forecast and historical points.
