# Held-out qualitative case audit

This audit records the four cases selected by `select_qualitative_cases.select()` after primary generation and native evaluation. The selector was deterministic: for each label contrast, it chose the lowest numeric task ID in each discordant direction, requiring both programs to be observed and eligibility-gated. These are illustrative post hoc examples, outside the four primary tests; they do not estimate failure frequencies or support mechanism claims.

All evidence was read from the exact prepared inputs, evaluator dataset, exported programs, and native reports:

- model-facing inputs and tests: `reproducibility/results/20260908_codex_mini_heldout200/controls/attempt2/input/prepared.jsonl` and `evaluator_dataset.jsonl`;
- exported programs: `reproducibility/results/20260908_codex_mini_heldout200/predictions/samples-single_roles.jsonl`, `samples-single_neutral.jsonl`, `samples-multi_roles.jsonl`, and `samples-multi_neutral.jsonl`;
- native details: the corresponding `reproducibility/results/20260908_codex_mini_heldout200/evaluations/<arm>/input/samples_eval_results.json` files.

## Single-call label contrast

**BigCodeBench/428, `single_roles` pass versus `single_neutral` fail.** Evidence is in `samples-single_roles.jsonl`, `samples-single_neutral.jsonl`, and `reproducibility/results/20260908_codex_mini_heldout200/evaluations/single_roles/input/samples_eval_results.json` plus the corresponding `single_neutral` report. Both programs perform an outer merge and scale numeric `df1` features. The role-labelled program scales a copy of `df1` before the one merge, so the result retains `df1` columns before `df2` columns. The neutral program first merges, then drops and reinserts the scaled `df1` columns through a second merge; its result order is `id, feature4, feature5, feature1, feature2, feature3`. The native report records `test_case_1` failing with an assertion that expected `['id', 'feature1', 'feature2', 'feature3', 'feature4', 'feature5']`. The natural-language task specifies the merge and scaling operations but does not explicitly state column order. The test therefore adds a stricter output-order contract; the observed failure is an implementation mismatch with that contract, not evidence about hidden reasoning.

**BigCodeBench/71, `single_neutral` pass versus `single_roles` fail.** Evidence is in `samples-single_roles.jsonl`, `samples-single_neutral.jsonl`, and `reproducibility/results/20260908_codex_mini_heldout200/evaluations/single_roles/input/samples_eval_results.json` plus the corresponding `single_neutral` report. Both programs parse the CSV, compute per-row sum and mean, and draw the requested histogram. The role-labelled program uses `Series.std(ddof=1)`, whereas the neutral program uses population standard deviation (`np.std`, `ddof=0`), as does the canonical solution. The role-labelled native report records failures in `test_case_2` (11.900380145988935 versus 11.017611134090766), `test_case_3` (8.568005268772557 versus 8.01463505095522), `test_case_4` (`nan` versus 0.0 for a single-element list), and `test_case_5` (47.95684491664328 versus 46.07544623291379). The prose says “standard deviation” without specifying the degrees-of-freedom convention; the executable test and canonical solution resolve that ambiguity in favor of the population definition.

## Three-call label contrast

**BigCodeBench/167, `multi_roles` pass versus `multi_neutral` fail.** Evidence is in `samples-multi_roles.jsonl`, `samples-multi_neutral.jsonl`, and `reproducibility/results/20260908_codex_mini_heldout200/evaluations/multi_neutral/input/samples_eval_results.json` plus the corresponding `multi_roles` report. Both programs generate a horizontal stacked bar chart and return a figure and axes. The neutral program chooses `max(2, min(5, num_types))` segments, so `num_types=10` creates 50 patches and `num_types=1` creates 2. The role-labelled program creates exactly `num_types` segments, producing the expected 100 and 1 patches. The native report records neutral failures in `test_case_3` (`50 != 100`) and `test_case_4` (`2 != 1`). The task says that values are generated across a specified number of categories and displayed as segments, but does not explicitly say that the number of segments must equal `num_types`; the tests impose that concrete contract.

**BigCodeBench/31, `multi_neutral` pass versus `multi_roles` fail.** Evidence is in `samples-multi_neutral.jsonl`, `samples-multi_roles.jsonl`, and `reproducibility/results/20260908_codex_mini_heldout200/evaluations/multi_roles/input/samples_eval_results.json` plus the corresponding `multi_neutral` report. Both programs count valid dollar-prefixed words and draw a bar chart. The neutral program retains `Counter` first-occurrence order. The role-labelled program sorts the counted items by descending frequency and then lexicographically. For the test text `This $is $is $is the $second $sentence $sentence`, the test expects categories `\$is, \$second, \$sentence` and values `3, 1, 2`; sorting places `\$sentence` before `\$second`, so `test_case_2` reports `Expected value '1.0', but got '2'`. The prose requires a frequency chart but does not prescribe category ordering; the test fixes first-occurrence order for this case. This is an observed ordering mismatch, not a causal or latent-role explanation.

The four cases show how executable contracts can distinguish programs when the prose leaves an output convention open. Their deterministic selection preserves the available discordances while avoiding any claim that these examples are representative of the full task population.
