# Coordinator validation of the partial-program diagnostic

The preparatory agent's initial completion reports overstated readiness. Reading
the emitted code showed that timeout statuses could disappear from summary
counts, sample identities were initially checked as globally unique tasks,
native sample order did not follow the original allocation, and the proposed
missing-report test asserted a hard-coded dictionary without calling the code.
The original report is preserved; its claims are superseded by the checks below.

The coordinator replaced native reconciliation with the existing exact official
report validator, added raw control-evidence validation and frozen source/input
binding, enforced the native runner's allocation order, verified retained sample
code, and rejected any new generated-test input outside the frozen inventory.
Pass, fail, timeout and unknown are retained per assignment. An invalid native
group cannot contribute diagnostic quality. Primary SCC quality remains null
for all 396 partial workflows regardless of diagnostic result.

Nine focused pytest tests pass in the study Python environment. They call actual
audit, setup-validation and report functions, including a missing native report,
timeout handling, invalid groups, repeated tasks across groups, wrong order,
tester-code substitution and a new unregistered input file. Native environment
fixtures are isolated only in unit tests; the real setup separately validates
both original controls and all frozen inputs.

The real v2 preparation contains 396 programs in groups 140/145/111. The actual
preflight report contains all 396 assignments with unknown native quality before
native execution. This is feasibility evidence for preparation and reconciliation,
not a claim that the programs have passed their tests. The separate protocol was
written before these native outcomes were inspected or the diagnostic was run.

Execution is queued after the main SCC native/analysis process. It uses the
unchanged official native runner, frozen image, original per-container limits,
and sequential diagnostic groups. The wrapper retains source/setup hashes and
refuses to proceed if the main queue did not complete successfully. No primary
record, model request, generated check or extraction rule is modified.
