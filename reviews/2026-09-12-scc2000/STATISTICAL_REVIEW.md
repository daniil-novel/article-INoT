# Statistical review: SCC 2000-block continuation

## Scope and decision

This is a preparation review of the proposed continuation. It uses the frozen SCC protocol, `scc_dispatch.py`, `scc_analyze.py`, and `reproducibility/task_dependence/PROTOCOL.md`. No model calls, Docker evaluation, candidate inspection, or benchmark-quality inspection was performed.

The continuation is statistically defensible only if the first 2,000 task-repeat blocks are made an immutable analysis and dispatch prefix before resumption. A block is one `(task_id, replicate_id)` with all three methods, so the target is 2,000 assigned blocks and 6,000 assigned method cells; the prefix can contain one, two, or three selected replicate IDs for a given task. It is not a target of 2,000 tasks or 2,000 successful responses. The eight interrupted assignments remain paused, unknown, and auditable; they receive no retry or replacement. The 3,000 blocks outside the prefix are administrative nonselection for this amendment: exclude them from its denominator while retaining them in the legacy 9,000-assignment ledger and report.

## Required freeze before resumption

Materialize and hash the exact first 2,000 blocks from the already frozen `cells(tasks)` output, including block order, task IDs, replicate labels, and the three method cells. The prefix must be defined by the original randomized schedule, not by completion status, quality, cost, or time. Record the amendment date and the fact that it was made after original calls had begun; it must not be described as preregistered before those calls.

The current dispatcher plans the full frozen inventory and scans every planned cell for pending work. Running it unchanged would eventually submit cells after block 2,000. The smallest operational fix is a hash-bound prefix manifest and a dispatcher filter that submits only prefix cell IDs, while asserting that every existing submitted cell in the archive is in the prefix (or is one of the eight documented interrupted cells). Out-of-prefix cells remain untouched. The existing method, model, prompt, runtime, randomization, and evidence files remain immutable. The 55-percent reserve stop, no-retry rule, and distinct unknown-usage accounting remain in force.

## Recommended unequal-repeat analysis

Use matched-repeat task differences. For contrast (c) and task (t), let (R_{tc}) be the selected replicate IDs in the prefix for which both SCC and (c) have observed native endpoints, and calculate (d_{tc}=|R_{tc}|^{-1}\sum_{r\in R_{tc}}(Y_{t,SCC,r}-Y_{t,c,r})). Average (d_{tc}) equally over control-eligible tasks with at least one matched repeat. Report the task count and the distribution of (|R_{tc}|). This is the observed matched-repeat estimand; it avoids giving a task extra weight merely because more of its repeats were observed.

Define the assigned-prefix estimand using the same selected replicate IDs, with (m_t) equal to the number of selected IDs for task (t): average all intended replicate differences within each selected task, then average those task means equally. Missing endpoint differences are unknown. This is distinct from the observed matched-repeat estimate and must be labelled as such. Do not treat replicate rows as independent tasks or weight tasks by repeat count.

Because interruption and transport failure can be related to method, call count, calendar time, or usage, report extreme bounds for the assigned-prefix estimand. For each selected task and contrast, use its fixed (m_t) denominator and assign every missing binary endpoint to 0 or 1 in the direction that minimizes or maximizes the contrast; then average task means equally. Report these bounds separately for all selected tasks and for control-eligible selected tasks. Administrative nonselection outside the prefix is excluded from this amended denominator; a never-submitted cell inside the prefix is missing and is not a failed model answer. A completed malformed answer remains an observed quality failure under the frozen rule. Transport, quota, authentication, provenance, workflow, and the eight paused records remain unknown.

The two SCC contrasts are the sole primary family and receive Holm adjustment at familywise alpha 0.05. Use a task-level paired analysis on the observed matched-repeat task differences, with no additional outcome-triggered tests. A two-sided one-sample t-test can remain the primary test if its use on this conditional estimand is stated explicitly. Do not add a sign-flip, mixed-model, inverse-repeat-weighted, or other new test after outcomes are seen. Any such sensitivity must be frozen before resumption. Repeat-count weighting would change the estimand toward tasks with more selected or completed attempts.

For uncertainty, use a 10,000-draw percentile bootstrap of whole tasks, seed 20260911, retaining all observed repeats within each sampled task and recomputing the task-level means and contrast. These intervals condition on observed complete pairs and do not repair informative missingness. Add the source-derived component bootstrap from the task-dependence protocol as a supplementary dependence sensitivity: resample components, keep all contributing tasks within each sampled component, and divide by sampled task count so large components do not become the point estimand. Report component count, largest-component share, effective task count, bootstrap variance, and any degenerate interval. A family-balanced mean may be shown descriptively only.

## Separate analyses and time effects

Run the original three-complete-repeat analysis as a separate, clearly labelled result: retain only tasks with all three repeats observed for both methods, preserve the two-contrast Holm family, and report its task bootstrap intervals. It answers a stricter complete-repeat estimand and must not be silently pooled with the unequal-repeat estimate. The original SCC protocol's SR-minus-SN and old200/new800 comparisons remain descriptive.

Preserve the randomized schedule and report completion by block position, method, replicate, and restart/calendar segment. The stop at the reserve threshold is an administrative stopping rule, not evidence of a quality outcome. If missingness or contrast estimates differ across predeclared schedule segments, restrict claims to the conditional observed prefix and show the sensitivity; do not select a segment after seeing quality. No claim should generalize beyond the frozen task list, model/dataset/transport adaptation, observed time window, and missingness assumptions. Null intervals cannot support non-inferiority or equivalence.

## Fatal implementation/statistical issue

The unchanged dispatcher would resume pending cells beyond the first 2,000 blocks, so prefix enforcement is a blocking correction. `scc_finish._records` does force `quality=None` for observed candidates from control-ineligible tasks, and also leaves unavailable candidates unknown; no quality leakage or demonstrated eligibility bias was found without inspecting outcomes. The issue in `scc_analyze.py` is an analysis boundary weakness: it calls primary contrasts on the all-task list and relies on null rows being excluded indirectly, instead of passing the eligible selected task set explicitly. The smallest fix is to enforce the prefix manifest, pass eligible selected tasks to the primary contrast routine, retain all-selected bounds, and add a separate matched-repeat path because `_quality_means` currently requires all three repeats.
