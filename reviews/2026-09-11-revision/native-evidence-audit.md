boundary. It is not a new manuscript review and does not authorize model,
Docker, or publication execution.

## Fixes applied in the SCC boundary

`scc_export.py` now refuses incomplete raw turn evidence while retaining
unparseable failed-turn usage as unknown, validates optional `result.json` and
`terminal_result.json` identities/states, validates every listed generated-test
status (and rejects generated-test infrastructure failure on a completed
assignment), joins completed requests to raw turn result/prompt/argv/usage
and file hashes, requires generated-test input/stdout/argv evidence, replays
the actual upstream SCC trajectory from archived messages and test feedback,
verifies the frozen single-arm prompt, checks candidate hashes, and keeps
observed empty-format answers distinct from never-started assignments.
Unfenced SR/SN responses normalize to the same empty candidate representation
as the dispatcher. It also checks the archive manifest and derives all nine
sample file bytes from the full ledger during resume validation.

`scc_finish.py` now invokes the pinned `scc_analyze` CLI in strict mode with
selection and control-gate files. Analysis has its own resumable stage with
logs outside the analysis output. Native and analysis stages can be reused
only when their saved command bytes exactly match the current command; failed
stage logs remain in place.

## Dispatcher findings for the SCC owner

The single-process path validates `runtime_provenance.json` on resume; the
`dispatch_processes` path currently validates only the stored runtime prefix
and does not perform the same native-executable/node-entry provenance check.
It also rewrites `commands.json` on resume without an explicit byte/hash gate.
These are dispatcher-side issues and were not changed here. Before treating a
multi-process archive as reproducible, add equivalent runtime and command
identity checks there.

The process parent skips any assignment directory that already has a
`status.json`, regardless of whether that status is terminal. A stale
`initializing` status therefore needs explicit recovery policy before resume;
otherwise it can be counted neither as pending nor as a validated terminal
attempt. The single-process path rejects such a state, so the two paths are
not yet equivalent.

Quota accounting and replenishment are structurally bounded: parent submission
uses the known-valuation guard, while workers return valuation and stop hints.
However, worker-generated result objects are not persisted as a separate
terminal result; the assignment status/raw evidence remains the source of
truth. Mixed method order is generated by the seeded `cells()` schedule and
exports are reordered by frozen selection order, which is compatible with the
ordered native evaluator once the generation matrix is complete.
