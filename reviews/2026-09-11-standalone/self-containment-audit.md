# Standalone self-containment audit

Дата: 2026-09-11. Read-only audit of the recursive English manuscript rooted at `sections/revision_en.tex` and the frozen methods/protocol sources. No live1000quality records were read, no experiments were run, and no manuscript or protocol was changed.

Цель аудита — перечислить сведения, которые читатель должен видеть в PDF, чтобы понять три разные серии без доступа к репозиторию. Это не требование воспроизвести provider responses из одного PDF: raw traces, source bytes and archives can remain supplementary materials. The manuscript should state the protocol and estimand in a self-contained way.

## Series boundary that must be explicit

The current manuscript reports the completed primary study: 200 task IDs, five conditions, 1,000 assignments, GPT-5.4 mini, medium reasoning, 1,797/1,800 calls with usage counters and 996 observed programs (`sections/revision_en.tex:19-23,37`; `sections/heldout_methods_en.tex:29-37`).

The prospective Luna extension is a separate study, not a result of the primary section: 1,000 task clusters (the original 200 plus 800 new IDs), five arms, three new repeat labels, 15,000 candidate assignments and 27,000 planned CLI turns (`reproducibility/scale1000_luna/PROTOCOL.md:9-31`; `generation_manifest.json`, fields `planned_candidates=15000`, `planned_cli_turns=27000`). The protocol says its outcomes are not executed data until the run is finished (`PROTOCOL.md:100-119`).

The pending SCC comparison is a third protocol: 1,000 tasks × three methods (SR, SN, pinned author-code SCC) × three repeats = 9,000 assignments, at most 18,000 model calls (`reproducibility/revision_20260911/scc_protocol.md:10-29`; `scc_manifest.json`, `planned_assignments=9000`). It is not a role-excised SCC arm and must not be presented as part of the completed 200-task primary result.

## Concrete PDF omissions and code-supported additions

1. **Series/status map (high priority).** The title, abstract, results and conclusion describe the completed 200-task primary study, but they do not give the reader a compact status map for the 15,000-assignment Luna extension and 9,000-assignment pending SCC protocol. Add one short “Study series and status” paragraph or table with the three counts above, model/settings, arms, and labels “completed primary”, “prospective extension”, and “protocol/pending”. This prevents the Luna plan or SCC protocol from being mistaken for reported outcomes.

2. **Task selection and repeat semantics.** The primary methods say “previously frozen, seeded random permutation” but do not print the seed, the deterministic ordering rule, or the exact 200 IDs in the method text (`sections/heldout_methods_en.tex:29-32`; code `reproducibility/benchmark_bridge.py:14,56-65`). State seed `20260908`, sorted IDs before shuffling, exclusion of `/0`–`/7`, and that the 200-task primary is one new repeat label. For Luna, state that the same 200 IDs plus first 800 unused IDs are retained and that repeat labels 101–103 are labels, not provider seeds (`scale1000_luna/PROTOCOL.md:9-17,26-31`). The task appendix can carry the long ID list.

3. **Exact treatment matrix across series.** The primary PDF defines D/SN/SR/MN/MR but does not place the Luna and SCC arm inventories beside it. Add the five primary/Luna arms and the separate SCC three-arm inventory in a compact table. The code and protocols support: D, SN, SR, MN, MR for the factorial study (`scale1000_luna/PROTOCOL.md:19-24`); SR, SN and `scc_author_2024_codex_transport` for SCC (`scc_protocol.md:10-18`). State that SCC versus SR/SN is a complete-workflow comparison, whereas SR–SN and MR–MN are component contrasts.

4. **Input boundary and forbidden information.** The PDF says that tests and references are not supplied, but a standalone methods paragraph should enumerate the actual model input fields and exclusions: task ID/prompt/context are prepared; evaluator `test` and `canonical_solution` are forbidden from model inputs (`reproducibility/heldout200/prepare_inputs.py:144-148`; `benchmark_bridge.py:68-75`). State that all prior exposed responses are forwarded in full for multi-call conditions, with no compression or selective truncation (`sections/heldout_methods_en.tex:5,37`; `scale1000_luna/PROTOCOL.md:19-24,35-40`).

5. **Generation and missingness rule for both completed and prospective series.** The primary text documents the 180-second deadline and amended continuation (`sections/heldout_methods_en.tex:37-39`), but the future Luna protocol uses 600 seconds, no retries, untouched-only resume, and retains invalid completed outputs as model failures (`scale1000_luna/PROTOCOL.md:33-55`). Add a sentence that these operational rules differ by series and that a submitted cell is never silently regenerated. This is needed to interpret missingness and avoids transferring the primary deadline to Luna.

6. **Extraction contract.** “Strict extraction selects the sole final Python block” is not enough for independent reading (`sections/heldout_methods_en.tex:42`). The implementation accepts exactly one fenced block whose language tag is `python`/`py` for BigCodeBench, with a newline after the opening fence and before the closing fence; zero or multiple eligible blocks produce an empty candidate and `format_extracted=false` (`reproducibility/benchmark_bridge.py:14-20,153-157`). Add this rule and state that no alternative block, repair or answer selection is used. It explains the two primary format failures in `revision_en.tex:21`.

7. **Native evaluator command and controls.** The PDF gives the benchmark mode and broad container limits, but not enough operational detail to identify the endpoint without a repository (`sections/heldout_methods_en.tex:42-46`; code `reproducibility/heldout200/run_observed_native.py:69-85`). Add a prose command description: BigCodeBench v0.1.4 `instruct full`, local execution, selective task IDs, `calibrated=False`, `no_gt=True`, parallelism 2, network disabled, non-root read-only container, 3 GB memory, two CPUs, and the fixed evaluator limits. State that the primary gate is 193/200 gold pass and 200/200 incorrect-control fail, while Luna reuses a gate with 985/1000 quality-eligible tasks (`scale1000_luna/PROTOCOL.md:57-72`). A full source commit or repository URL is unnecessary for this self-contained description.

8. **Quality endpoint and control interpretation.** The current text says native tests determine success and reports eligibility, but should state the exact binary endpoint: candidate passes only when the extracted program receives the native pass status; reference-ineligible tasks stay in assignment/resource denominators and are removed from quality-pair eligibility (`sections/heldout_methods_en.tex:20,44-46`; `scale1000_luna/PROTOCOL.md:61-65`). Also retain the limitation already present: controls establish executability and negative discrimination, not semantic validity of every benchmark assertion (`heldout_methods_en.tex:44`).

9. **Statistics must be series-specific.** The completed primary uses four paired McNemar tests with Holm correction and task-bootstrap intervals (`sections/heldout_methods_en.tex:48-51`). The Luna extension instead averages three binary outcomes within each task, uses task-level paired t-tests for four primary contrasts, Holm over four hypotheses, and whole-task bootstrap with seed 20260909 (`scale1000_luna/PROTOCOL.md:74-98`). The SCC protocol uses task-cluster means of three repeats, two primary contrasts (SCC–SR and SCC–SN), Holm over two hypotheses, and bootstrap seed 20260911 (`scc_protocol.md:99-122`). Add these rules only as protocol descriptions for unreported series; do not merge their p-values or denominators with the completed primary family.

10. **SCC feedback, access and adaptation.** The current feasibility section describes the author-code pilot, but a self-contained PDF needs one sentence for the pending main SCC protocol: its generated-test report is internal workflow feedback; generated tests receive neither benchmark hidden tests nor reference programs; native BigCodeBench evaluation is a separate endpoint (`scc_protocol.md:14-19,40-49`). State that the adapter uses `max_round=2` (analyst, initial coder, tester, at most one coder repair = at most four model calls), while the upstream constructor default is 4; this is a configured adaptation, not paper MI=4 (`external_baselines/scc.py:69-80`; `revision_20260911/scc_dispatch.py:95-96`; `vendor/scc_2024/session.py:8-12`). Explicitly say the 9,000-assignment SCC series has no role-excised SCC condition.

## Commit/repository references to remove or replace in the PDF

The main standalone blocker is `sections/revision_en.tex:87`, which currently names a repository, a commit, a directory and public-archive byte-for-byte replay. Replace it with a concise supplementary-material statement: “Prompts, task IDs, candidate programs, native reports, assignments, source/environment identities and per-call counters are retained in supplementary materials; the paper reports the protocol and aggregate evidence, while raw provider traces are not reproduced by the PDF.” Do not promise replay from the PDF itself.

Other method text contains source identifiers that should be converted to descriptive version labels if the no-commit/no-repository policy applies throughout the PDF: `sections/heldout_methods_en.tex:42` (abbreviated evaluator commit), `sections/scc_feasibility_en.tex:3,5` (author revision and source-code citation), `sections/swe_demonstration_en.tex:4,8` (base commit and amendment commit), and `sections/segregation80_methods_en.tex:12` (plan commit). The experiment can remain identifiable by benchmark version, CLI version, model, container restrictions, source/environment hashes and exact command semantics; no external repository is needed for the reader to understand the estimands.

## Boundary of this audit

These are self-containment repairs and status clarifications, not claims that the prospective Luna or SCC series has outcomes. The completed primary result remains the 200-task GPT-5.4 mini study; Luna is 15,000 planned assignments; SCC is 9,000 planned assignments. Raw archives, checksums and replay tooling may remain supplementary, but the PDF must not imply that a reader can deterministically re-run provider generations from the article alone.
