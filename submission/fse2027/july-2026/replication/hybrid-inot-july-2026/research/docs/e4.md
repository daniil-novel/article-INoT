# E4 — самопроверка малой моделью и гипотеза H2

**Связь со статьёй:** §7.5. Эксперимент проверяет неравенство:

```text
C_check^S < (ρ0 − ρ1) · C_rerun^L
```

## Что делает эксперимент

Для каждой задачи:

1. Запускается `B0_SingleLarge` на большой модели.
2. Сохраняются стоимость, токены и verdict.
3. Полученное решение отправляется малой модели с prompt-ом `PASS / REJECT`.
4. Считается, сколько дорогих rerun-ов удалось бы избежать.

Оцениваются:

- `ρ0` — вероятность необходимости rerun без малой проверки;
- `ρ1` — вероятность необходимости rerun после малой проверки;
- `C_check^S` — средняя стоимость проверки малой моделью;
- `C_rerun^L` — средняя стоимость одного повторного вызова большой модели.

Per-task margin:

```text
margin_i = saved_i - check_i
saved_i = I[B0 ошиблась и малая модель отклонила решение] · large_cost_i
```

H2 подтверждается на датасете, если нижняя граница bootstrap CI 95% для
среднего `margin_i` больше нуля.

## Как воспроизвести

```bash
# Спецификация статьи: 100 HumanEval + 50 SWE-bench Lite
python -m inot e4 --n 100 --seeds "42,123"

# Быстрый пилот
python -m inot e4 --n 20 --seeds "42"
python -m inot view e4
```

Если SWE-bench Lite недоступен, код использует Synthetic Tool-Use Suite как
второй набор задач и явно пишет это в результатах.

## Артефакты

Результаты сохраняются в `results/e4/{humaneval,swebench_lite|synthetic_tool_use_suite}/`.

- `runs_b0.json`;
- `summary.json` с `ρ0`, `ρ1`, `C_check^S`, `C_rerun^L`, margin и CI;
- `fig_h2_savings.png` — гистограмма per-task net margin;
- `H2_VERDICT.md` — общий вывод по наборам данных.

## Почему дизайн эксперимента корректен

- H2 является экономическим утверждением, поэтому измеряется именно стоимость
  реальных API-вызовов.
- Bootstrap строится по per-task margin, а не по разности агрегированных средних.
- Это сохраняет вариативность задач, которую аналитическое неравенство скрывает
  под математическим ожиданием.
