# E3 — масштабирование по длине контекста и оценка τ*

**Связь со статьёй:** §7.4. Эксперимент проверяет утверждение о существовании
пороговой длины контекста `τ*`, после которой Hybrid-INoT начинает выигрывать
у Classical-MAS по токенной эффективности.

## Что измеряется

Для `|C0| ∈ {256, 1024, 4096, 16384}` и архитектур `B0 / B2 / B3` считается:

```text
U_tok = pass@1 / (T̄ / 1000)
```

Затем ищется минимальная длина контекста, где кривая B3 становится не хуже B2.

## Как оценивается τ*

1. Строятся средние кривые `U_tok` для B2 и B3.
2. Находится первая точка, где `U_tok(B3) - U_tok(B2) >= 0`.
3. Если пересечение лежит между измеренными длинами, используется линейная
   интерполяция.
4. Для устойчивости оценки выполняется bootstrap по задачам внутри каждого
   bucket-а `(архитектура, контекст)`.

## Условие практической поддержки H1

H1 практически поддержана, если `τ*` конечна и меньше 16384 токенов.

## Как воспроизвести

```bash
# Спецификация статьи: 50 задач × 4 длины контекста × seed-ы
python -m inot e3 --n 50 --seeds "42,123,456,789,1337"

# Быстрый пилот
python -m inot e3 --n 10 --seeds "42"
python -m inot view e3
```

## Артефакты

- `tau_star.json` — точечная оценка, bootstrap CI, медиана и доля bootstrap
  выборок с конечным пересечением.
- `fig_utok_vs_context.png` — кривые `U_tok(|C0|)` с отметкой `τ*`.
- `fig_delta_utok_vs_context.png` — разность `U_tok(B3) - U_tok(B2)`.
- `runs.json`, `table.txt`, `summary.json`.

## Почему дизайн эксперимента корректен

- Одна точка `τ*` без доверительного интервала недостаточна, поэтому используется bootstrap.
- `finite_share` показывает, насколько часто пересечение вообще появляется
  в проверяемом диапазоне.
- График разности помогает увидеть не только уровень метрики, но и смену режима.
