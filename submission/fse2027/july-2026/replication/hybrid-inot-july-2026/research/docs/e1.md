# E1 — H1 на HumanEval и controlled-context наборе

**Связь со статьёй:** §7.2. Эксперимент проверяет гипотезу **H1**:
Hybrid-INoT должен быть токенно эффективнее Classical-MAS на длинном контексте.

## Что измеряется

Для каждой архитектуры **CTRL NoAssistant**, **B0 SingleLarge**,
**B1 SelfRefine**, **B2 ClassicalMAS**, **B3 HybridINoT** и для каждой длины
контекста `|C0| ∈ {512, 2048, 8192}` измеряются:

- `pass@1` — доля задач, решённых с первой попытки;
- `T̄` — среднее число токенов на задачу;
- `U_tok = pass@1 / (T̄ / 1000)` — формула (17);
- `Q$ = pass@1 / C̄_inf` — формула (18);
- `VCR` — verified candidate rate, формула (19);
- `MAS_i` — агрегированная метрика качества и поддерживаемости, формула (20);
- стоимость в USD и RUB;
- объём передачи контекста между LLM-вызовами;
- число context handoff events, то есть сколько раз архитектура заново
  передаёт контекст в отдельный role/model call.

## Как проверяется H1

1. Для B2 и B3 строятся парные массивы `U_tok`, выровненные по `(task_id, seed)`.
2. Запускается парный критерий Вилкоксона.
3. Для среднего `ΔU_tok` считается bootstrap CI 95% с 10 000 ресэмплирований.
4. Для множественных сравнений применяется поправка Холма-Бонферрони.
5. Для `pass/fail` дополнительно считается McNemar.

H1 считается подтверждённой на максимальном контексте, если:

- прирост `U_tok` B3 относительно B2 не меньше 15%;
- `pass@1` B3 не хуже B2 более чем на 2 процентных пункта;
- сравнение B3 против B2 статистически значимо после Holm-Bonferroni.

## Как воспроизвести

```bash
# Проверка без API и без затрат
python -m inot check

# Полная спецификация статьи: 164 задачи × 3 контекста × 5 seed-ов
python -m inot e1 --n 164 --seeds "42,123,456,789,1337"

# Быстрый пилот
python -m inot e1 --n 20 --seeds "42,123"

# HumanEval + controlled-context набор из курсовой
python -m inot e1 --n 20 --seeds "42,123" --suite both

# Только controlled-context набор
python -m inot e1 --n 20 --seeds "42,123" --suite controlled

# Красивый просмотр результатов в терминале
python -m inot view e1
```

## Почему дизайн эксперимента корректен

- Все архитектуры получают одинаковые задачи, seed-ы, модели и длины контекста.
- Различается только способ организации ролей и передачи контекста.
- HumanEval-контекст строится из соседних задач и не содержит решение целевой задачи.
- Controlled-context набор фиксирует семейства задач и масштабирует только
  длину контекста, чтобы изолировать переменную `|C0|`.
- `CTRL_NoAssistant` даёт контрольную точку “без ассистента”.
- На графиках по длине контекста красная линия показывает порог H1.
