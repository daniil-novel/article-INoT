\section{Subscription-based Codex development experiment}\label{sec:codexpilot}

\subsection{Model, assignments and observed usage}
To remove the immediate dependence on a funded OpenRouter key, we implemented a separately specified development experiment using \texttt{gpt-5.4-mini} with \texttt{medium} reasoning through a ChatGPT-authenticated Codex CLI. This model has an explicitly published API price and is described as coding-capable~\cite{openai54mini2026,openaipricing2026}. It is an economical coding choice; lower-priced nano-class models exist, so this is not a claim to use the cheapest possible GPT. Spark is excluded from the study because a standard API price for it was not established. Its arithmetic preflight is not benchmark evidence.

The frozen development assignment contains eight tasks from the previously randomized development permutation, five treatments and one replicate: 40 candidate solutions and 72 planned fresh CLI turns. Four treatments cross one/three turns and neutral/role-labelled stages; the fifth is a direct solver without prescribed stages. The selected task suffixes are 325, 322, 1036, 1005, 361, 1087, 45 and 309. No confirmatory task was accessed for model generation. Cell submission order is randomized and two generations may run concurrently; the archive preserves their actual order and timestamps. The sample is a feasibility pilot, not 40 independent tasks.

Every stage receives the full task, supplied context and earlier exposed stage outputs. Shell, browsing, apps, plugins and delegation are disabled; the working directory is empty and the sandbox is read-only. Each turn starts a fresh ephemeral CLI thread. Full prompts, instructions, arguments, stdout JSONL, stderr, returned usage and all intermediate/final text are retained with hashes. A named authenticated provider uses HTTPS and zero configured request/stream retries. Errors, tool events, compaction events and incomplete usage cannot silently become successful observations.

An initial attempt using CLI 0.144.1 stopped after 12 complete generations because a neutral planning stage invoked the built-in planning tool. All 21 submitted turns are retained, including the invalid trace: 144,321 observed tokens correspond to USD 0.2493285 at the stated rates. This entire attempt is excluded from treatment comparisons. CLI 0.153.4 then enabled explicit removal of the planning tool~\cite{codexrelease2026}, followed by a separately frozen replacement matrix with unchanged task IDs, prompts and randomization. The replacement does not reuse the first attempt's successful cells. Other model-dependent built-ins cannot all be removed through configuration, so tool-free execution is checked in the actual event stream, not assumed from the settings.

\subsection{What the subscription channel does and does not control}
The inspected CLI exposes \texttt{turn.completed.usage}, including input, cached input, output and reasoning-output counters~\cite{codexexec2026}. These are observed CLI-turn totals. The stream does not expose a complete raw backend HTTP request, guarantee an immutable served weight snapshot, or independently enumerate every internal backend request. The requested model alias and CLI version are recorded; the published API snapshot is not claimed to be verified from the response.

The CLI experiment does not enforce the original 12,288-token matched output allowance and does not expose a verified sampling seed or temperature control. All cells use medium reasoning with native stopping. A replicate identifier is not a model seed. Accordingly, this pilot studies the specified Codex protocol; it cannot be pooled into the original fixed-output-budget experiment. These differences are documented before task generation, rather than retroactively treated as equivalent controls.

\subsection{Transparent valuation and executable controls}
Let $I$, $C$ and $O$ denote the observed input, cached-input and output counts. The standard API list prices accessed on 8 September 2026 give
\begin{equation}
 V=\frac{0.75(I-C)+0.075C+4.50O}{10^6}\quad\mathrm{USD}.
\end{equation}
Cached input is already part of $I$; reasoning output is already part of $O$. Adding either subset again would double-count tokens. We additionally report the no-cache sensitivity $V_0=(0.75I+4.50O)/10^6$. Cache hits depend on the observed execution schedule and are not an independently randomized treatment; total-token results and $V_0$ distinguish prompt repetition from the price discount. Both values are \emph{counterfactual API-equivalent valuations}, not actual subscription charges, OpenRouter spending, or estimates of OpenAI's internal compute cost. The included subscription has shared usage limits; access is not assumed unlimited.

We first run pinned upstream \texttt{bigcodebench.eval.untrusted\_check} with the official v0.1.4 tests inside a restricted development container. We then execute the unchanged official \texttt{bigcodebench.evaluate} CLI in an extended, version-recorded container, using local execution, the instruct split and exactly the same eight IDs. This is a selective official-CLI run in a custom environment, not the full official release image or a full-benchmark score. Separate native gold and deliberately incorrect runs determine eligibility; \texttt{no\_gt=True} disables internal ground-truth caching, and calibration is disabled. All 40 raw native CLI statuses match the upstream-core results and every reported solution matches its archived extracted code. Networking is disabled and image/source/package/solution hashes are recorded. A task is evaluable only if its reference passes and the negative control fails; unresolved environments remain missing for every treatment. All assigned tasks remain in the denominator, with optimistic/pessimistic bounds. No official SWE-bench or native-agent result follows from this pilot.
