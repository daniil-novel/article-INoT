\section{Introduction}
\label{sec:heldout-context}
Planning, implementation and review can be written as stages within one response or distributed over successive model calls. Calling those stages agents introduces a second change: role-specific wording. Comparisons that also summarize the input cannot determine which change explains a resource saving or a quality difference. In particular, a cheaper compressed response does not establish a benefit from internal role separation. This identification problem motivates a controlled test of labels and call boundaries using executable code tasks.

The intervention of interest is precise. Neutral stage numbers and the names planner, implementer and reviewer accompany identical operation sentences. Independently, those operations are requested in one fresh model turn or three fresh turns with the entire visible history forwarded. Every condition receives the same full task and supplied context. A direct one-call implementation instruction provides the simplest comparator. Thus the label contrasts isolate wording within a fixed topology, while the topology contrasts include intermediate information flow and repeated inference. Neither interpretation requires a claim that role names create independent latent agents.

The study separates a 40-task development stage from a 200-task reserved allocation, applies original executable BigCodeBench tests, and evaluates a separately frozen INoT PromptCode adaptation on the same reserved tasks. A one-issue SWE-bench demonstration supplies a limited repository-repair boundary. Quality has an opportunity to vary on these tasks, and every assigned cell remains visible even when generation or reference controls fail. Published GPT-5.4 mini tariffs permit an explicit resource valuation from actual subscription-channel counters, with a separate sensitivity to cache discounts.

The contribution is a controlled replication and extension of role-based code-generation studies: a compression-free $2\times2$ measurement with a direct comparator, four predeclared paired quality contrasts and explicit missingness, supported by a complete exposed-response, program, native-report and token archive. The empirical claim is restricted to the frozen prompts, the requested model alias and the sampled tasks. The research question concerns whether role labels and call boundaries improve the measured quality--resource tradeoff under these conditions.

INoT describes compact PromptCode instructions for internal dialogue and reasoning~\cite{sun2025inot}. This motivates evaluating a disclosed algorithm adaptation, while a separate minimal label intervention addresses whether named roles themselves change results. The two comparisons answer different questions: the INoT instruction changes the reasoning procedure, whereas the factorial label contrast preserves the operation sentences. The original Hybrid-INoT comparison additionally changed compression and reruns; its historical records are retained as background rather than pooled with the new experiment.

Single- versus multi-agent work under matched thinking-token budgets emphasizes that additional calls and additional computation are distinct interventions~\cite{tran2026budget}. Here, actual completion length is not held to a matched hard budget. Instead, token components and list-price valuations are reported as measured outcomes alongside quality. That design describes the implemented protocols' tradeoffs and does not establish optimal allocation at a fixed inference budget.

Agentless uses a structured localization--repair--validation workflow~\cite{xia2024agentless}; SWE-agent couples the model to a repository interface~\cite{yang2024sweagent}. Both introduce retrieval, tools and environment interaction beyond fixed-context function generation. Their published scores cannot be inserted into a paired matrix with different tasks and settings. BigCodeBench~\cite{zhuo2024bigcodebench} supplies diverse library-dependent tasks with executable tests, while SWE-bench~\cite{jimenez2023swebench,swebenchdocs2026} measures repository changes against issue-specific tests. Native evaluation strengthens outcome validity, but passing a reference control does not settle every natural-language instruction/test disagreement.
